If one upload is spent, spend it on France only: drop word IDF and English legal-form lists, keep character comparisons and exact house numbers, and freeze the threshold at the worse US–India macro F0.5. ## Reweighting already ranked the public file backward

Stop selecting on reweighted dev macro F0.5, and stop rebuilding the dev set by adding ownerless records until the leaderboard winner sits on top. The replacement, runnable in a day on pairs that already exist, is a sensitivity sweep over an analyst-chosen non-match rate for one input-defined pattern. It uses train labels and unlabeled test inputs. It does not identify test macro F0.5.

The ordering failure is already measured, and it is small in a way that makes ordinary validation look stable while pointing backward. Entity-level conflicts, stage-2 match and judge veto, sit at **0.015** per Source 1 entity on dev and at **0.145** (US), **0.100** (India), and **0.295** (France) on test. Ownerless Source 2/3 records sit near **2.29** per Source 1 on test against **1.22** on dev, about **1.9×**. Inside a score band, a dev-versus-test adversary reaches AUC **0.88** on US and **0.83** on India, led by the house-number relation, place-IDF sums, name-frequency counts, and same-house counts. Among confident US pairs, a house number that differs only in the last digit is **0.8%** of dev and **2.5%** of test, and on labelled dev that pattern is a true match **95%** of the time. The later files added about **15k** such US pairs over the **0.985** file. None of those figures is a published result, and none of them is \(P(\text{match} \mid \text{pattern})\) on test. A public gap of about **0.00025** macro F0.5 is a handful of entity-level failures once it is multiplied by the number of scored Source 1 entities. That count is not in the measurements, so the gap is not a known number of false merges. Blocking already retrieves **99.75%** of true pairs, and the team bounds the missing pairs at no more than about **+0.0008** macro F0.5. Retrieval is not the repair.

Covariate-shift reweighting is the valid selector only when \(P(Y \mid X)\) is the same law on dev and test and only \(P(X)\) has moved ([Shimodaira, JSPI 2000](https://www.sciencedirect.com/science/article/abs/pii/S0378375800001154); [Sugiyama et al., JMLR 2007](https://www.jmlr.org/papers/volume8/sugiyama07a/sugiyama07a.pdf)). Label-shift reweighting is the valid selector only when \(P(X \mid Y)\) is unchanged and the new class prior is what moved, which black-box shift estimation recovers from a source confusion matrix without test labels ([Lipton, Wang, and Smola, ICML 2018](https://arxiv.org/abs/1802.03916)). A change in \(P(\text{match} \mid \text{pattern})\) for a rare pair type is real concept drift in the stream sense, with or without a change in \(P(X)\), and neither weight is a functional of that conditional ([Gama, Žliobaitė, Bifet, Pechenizkiy, and Bouchachia, ACM Computing Surveys 2014](https://dl.acm.org/doi/pdf/10.1145/2523813)). Moreno-Torres et al. reserve the name "concept shift" for the case where the conditional moves and the marginal does not; a joint move is residual dataset shift, and it is still not fixed by an \(X\)-only weight ([Moreno-Torres et al., Pattern Recognition 2012](https://sci2s.ugr.es/sites/default/files/ficherosPublicaciones/1425_DatasetShift_TerminologyReview_PR_3rdRD_11_paper_JournalVersion.pdf)). Adversarial AUC detects a change in \(P(X)\). The adversary never sees \(Y\), so it cannot tell virtual drift from a changed conditional. Counts and IDFs that depend on split size move \(P(X)\) even when the businesses do not. A density ratio fit on those coordinates estimates the artifact. Target accuracy is not identified from labelled source data plus unlabeled target inputs without a further assumption, so no label-free score, including this sweep, is a consistent estimator of the public number for an arbitrary shift ([Garg, Balakrishnan, Lipton, Neyshabur, and Sedghi, ICLR 2022](https://arxiv.org/abs/2201.04234)). These two files already break accuracy-on-the-line: the better dev file is the worse public file ([Miller et al., ICML 2021](https://proceedings.mlr.press/v139/miller21b.html)). Training-domain validation is the rule that would have uploaded the loss.

Run four scores and do not average them into a "corrected dev." Keep the leaderboard number out of the fitting loop. First refit the adversary inside the same score band after the frequency features are replaced by pooled rates, or after they are dropped. If AUC collapses, the **0.88** and **0.83** were mostly split-size artifacts and must not become weights. If the house-number relation still separates the splits, that covariate is the one a prevalence weight is allowed to use. Estimate any remaining ratio directly, by KLIEP rather than by dividing two densities, and flatten it; full importance weights are high-variance, and the finite-sample optimum is often a weight between uniform and the full ratio ([Sugiyama et al., Annals of the Institute of Statistical Mathematics 2008](https://www.ism.ac.jp/editsec/aism/60/699.pdf); [Shimodaira 2000](https://www.sciencedirect.com/science/article/abs/pii/S0378375800001154)). Record effective sample size. If that size cannot resolve a gap of a few **\(10^{-4}\)**, the weighted ranking is not evidence. Second, as a negative control only, upweight labelled dev entities in the last-digit pattern so its rate matches the unlabeled confident-US rate, **2.5%** against **0.8%**, and separately upweight ownerless records by about **1.9×**. Score macro F0.5 with a correct empty prediction equal to **1.0**. A version of this already failed. Repeat it only on the cleaned features. If **0.985** is still not first, stop explaining these files as covariate shift. Do not tune the weight until it is first. That search is a leaderboard fit.

Third, build the lookalikes by changing the label, not by reweighting it. Define the pattern from inputs alone: house numbers differ only in the last digit. Do not flip gold matches to non-matches, because that confounds recall with the false-merge question. Copy a labelled true match, change the last house-number digit, and label the copy a non-match. That construction can be scored only if the frozen matcher runs on the edited pairs. Sweep the injected non-match rate across the labelled negative rate of about **5%**, then **20%**, **50%**, and **80%**, and keep one arm that adds pattern mass without changing the conditional. The prevalence-only arm should agree with the negative control. Rank frozen files by how fast macro F0.5 falls as the injected rate rises, not by the score at a single rate. A file that merges more of the injected non-matches falls faster. It ranks **0.985** above the later files only if that file in fact commits fewer of those merges and the rest of the metric does not offset them. That comparison has not been computed. Choosing the rate that reproduces the public order would be fitting the leaderboard. If only submission files remain, and new pairs cannot be scored, report the count of predicted merges on unlabeled test pairs in the pattern and the pairwise precision under the hypothetical label. Label that number a proxy. It is not macro F0.5, because entity-level F0.5 needs the other gold links for a test entity, which are absent. A few hundred injected decoys make each extra false merge a large fraction of the synthetic score on purpose. Do not report the synthetic score as **0.985** versus **0.98475**. Fourth, beside the sweep, report source-slice macro F0.5 on the last-digit pattern, on ownerless dev entities, and by country, using dev labels only. With a **95%** positive slice the gap between files near **0.99** is noisy; a skewed validation slice is exactly where worst-slice selection becomes unstable ([Sagawa, Koh, Hashimoto, and Liang, ICLR 2020](https://arxiv.org/html/1911.08731v2)). If the files tie on every source slice and separate only as the injected rate rises, the damage sits outside the dev conditional. That is the situation the failed reweighting was already pointing at.

What unlabeled inputs identify is the test prevalence of the pattern inside the confident band, the ownerless rate, covariate separation after the artifact check, each frozen file's merge rate on the pattern, and the slope of a rescorable file against an assumed non-match rate. What they do not identify is \(P(\text{match} \mid \text{pattern})\) on test, whether the **0.8%** to **2.5%** gap is decoys or more true typos or a model admitting pairs it was trained to like, whether the judge conflicts and the last-digit pairs are the same pairs, and the public macro F0.5. Agreement-on-the-line and confidence-threshold predictors of target accuracy are not the decision rule: the files already violate the line, and the errors at issue are high-confidence merges, which a confidence threshold is built to trust ([Baek, Jiang, Raghunathan, and Kolter, NeurIPS 2022](https://arxiv.org/abs/2206.13089); [Garg et al., ICLR 2022](https://arxiv.org/abs/2201.04234)). No public entity-resolution writeup found here built a higher hard-negative dev set and then showed it reordered two named submissions the way a shifted test did. The nearest design, extra in-fold candidates plus a double weight on false positives, was a reaction to group cross-validation diverging from a product-matching leaderboard, and the authors call it leaky and do not state that it restored the order ([Shopee 4th-place writeup](https://www.kaggle.com/c/shopee-product-matching/discussion/238295)). Extrapolating a threshold along gallery size made a private score worse, **0.762** and **0.757** ([Shopee 7th-place writeup](https://www.kaggle.com/c/shopee-product-matching/discussion/238174)). The fraud case in which a dev-versus-leaderboard break was actually repaired used time and client identity, not synthetic neighbours, and the adversary's AUC near **1** was a population change rather than a concept change ([Deotte, IEEE-CIS 1st place](https://www.kaggle.com/competitions/ieee-fraud-detection/discussion/111284)). The falsifier, with no new test labels, is a sweep in which the **0.985** file does not lose less synthetic F0.5 as the injected rate rises. Then these files do not differ on this pattern, or the public gap is not extra false merges of it. Do not search patterns until the public order appears.

## A tenfold veto rise is a prior, and France's 11.6% is not

Do not multiply the stacker's judge coefficient by the conflict ratio. On a group that passes a constant-likelihood check, shift the match prior and keep the source Bayes factor. On a group that fails it, stop using that factor. The label-free output is then an interval, and at France's high-score veto rate the interval says a strong source factor is illegal if the **0.999** score is taken seriously. Trust in the judge does depend on the region. The dependence is a change of prior in US and India, and a refusal of the source factor in France. It is not a larger coefficient where vetoes are more common.

Inside a bin of the features one conditions on, the veto rate is an identity, not a finding: \(r = f\pi + t(1-\pi)\), with \(f\) the false-veto rate among true matches, \(t\) the true-veto rate among non-matches, and \(\pi\) the match prior in the bin. Three unknowns, one unlabeled observable. A higher \(r\) does not say which one moved. Under a constant judge likelihood, \(f\) and \(t\) taken from labelled US or India in the same bin, the unlabeled rate identifies the prior, \(\hat\pi = (t - r)/(t - f)\), when that value lies in \([0, 1]\). The weight that multiplies prior odds after a veto is \(K = f/t\). It does not grow with \(r\). Decoy density changes only the prior odds. Relative to the source bin those odds scale by \((\delta_s/\delta_g)\cdot((1-\delta_g)/(1-\delta_s))\), which is approximately \(\delta_s/\delta_g\) only when decoys are rare. In a saturated logistic bin a pure prior change moves the intercept. The veto contrast stays put. Scaling the coefficient "in proportion to decoy density" overstates the veto in exactly the regime where the likelihood ratio was stable. This is Fellegi–Sunter arithmetic: posterior odds equal prior odds times \(m/u\), and a veto has \(m = f\) and \(u = t\) ([Linacre, 2023](https://www.robinlinacre.com/m_and_u_values/)).

The US and India test conflict rates, about tenfold and about sevenfold the dev rate of **0.015**, can still be that prior story if leave-one-country labels say \(f\) and \(t\) actually traveled and if \(t\) is not tiny. France cannot be read the same way. Treat the in-country test rate at \(p \ge 0.999\), about **0.08%**, as a stand-in for \(f\) only because \(\pi\) is near 1 on the source, which is itself an assumption. Even a judge that vetoes every non-match (\(t = 1\)) and keeps \(f = 0.0008\) cannot produce \(r = 0.116\) unless the non-match mass in that bin is at least about \((0.116 - 0.0008)/(1 - 0.0008) \approx 0.115\). So either more than about one in nine of France's \(p \ge 0.999\) pairs are non-matches, or \(f\) rose, or both. A nominal score of **0.999** cannot absorb an **11.5%** non-match rate unless the score itself is wrong on France. A ten- to twenty-fold rise from **0.08%** lands near **0.8%** to **1.6%** and, under \(t \le 1\), requires only on the order of **1%** non-matches. Constant likelihood is a possible reading of a modest in-country rise. It is not a possible reading of **11.6%** unless the anchor prior in that bin is far below **0.999**. If one assumes \(\pi \ge 0.999\) anyway, the France posterior bound is \(P(\text{match} \mid \text{veto}) \ge 1 - 0.001/0.116 \approx 0.991\). The veto should barely move a **0.999** score. That interval is illustrative arithmetic on the team's rates, with no sample size and no standard error. Do not substitute **11.6%** for a measured false-veto rate.

Saerens EM and black-box shift estimation implement only the constant-likelihood case. They reweight a frozen posterior by a new prior, or invert a source confusion matrix, under \(P(X \mid Y)\) fixed ([Alexandari, Kundaje, and Shrikumar, ICML 2020](https://ar5iv.labs.arxiv.org/html/1901.06852); [Lipton, Wang, and Smola, ICML 2018](https://arxiv.org/abs/1802.03916)). Fed a score that still contains the judge, they read every extra veto as a prior shift, including in the broken-judge regime, and then the veto looks more informative. That is the wrong direction once \(f\) has risen: \(K = f/t\) moves toward 1, and the veto should move the probability less. Platt scaling and temperature scaling need labels; a slope refit pretends the likelihood ratio changed, and a temperature is not a prior correction ([Platt scaling](https://en.wikipedia.org/wiki/Platt_scaling); [Alexandari et al., ICML 2020](https://ar5iv.labs.arxiv.org/html/1901.06852)). Covariate-shift importance weighting assumes \(P(Y \mid X)\) is the same on the target, so it never revises a coefficient because reliability changed ([Sugiyama's covariate-shift review](http://www.ms.k.u-tokyo.ac.jp/sugi/2012/CSAreview.pdf)). Learning to defer needs labels of whether the expert is right ([Mozannar and Sontag, ICML 2020](https://ar5iv.labs.arxiv.org/html/2006.01862)). No method reviewed here both uses only source labels plus unlabeled target scores and point-identifies a new judge coefficient when the prior and \(f\) move together. Record-linkage EM can move \(m\) and \(u\) from unlabeled agreement patterns only inside a mixture that the comparison vector identifies; one binary judge bit plus a free prior is one equation and three unknowns, and a wrong independence assumption does not become identified because the veto rate changed ([Winkler, Census RR2000/05](https://www.census.gov/content/dam/Census/library/working-papers/2000/adrm/rr2000-05.pdf); [Brown et al., BMC Medical Research Methodology 2017](https://bmcmedresmethodol.biomedcentral.com/articles/10.1186/s12874-017-0370-0)).

The procedure that matches those limits does not refit the stacker. On labelled US and India, bin a judge-free score \(s_0\), meaning stage-2 \(p\) together with the competition features, not the marginal of \(p\) if those features are in the model. Estimate \(f_s(s_0)\), \(t_s(s_0)\), and the reliability of \(s_0\). Binning on \(s_0\) avoids pretending the judge is independent of the other features given \(Y\); that independence is false if the judge reads the same fields, and imposing it double-counts. Bins with no labelled non-matches do not yield \(t_s\). At \(p \ge 0.999\) the denominator of \(K_s = f_s/t_s\) is the unstable object, and the team did not report how many labelled non-matches sit there. Propagate that uncertainty. \(f_s \approx r_s\) is the better-identified source quantity. Leave one country out: freeze \((f, t)\) from one country, invert the other country's unlabeled veto rate, and compare the implied prior with that country's true \(P(Y = 1 \mid s_0)\). This is the only empirical check that "more vetoes meant more decoys" between US and India. It uses labels. It says nothing about France by itself. A separate US-only judge vetoed **1.54%** of India's \(p \ge 0.999\) pairs against **0.06%** in-country, and every one of those vetoes was a true match. That is direct evidence that \(f\), not only \(\pi\), moved on that labelled slice. It is a different system from the test judge, and it is not a measurement of test-France \(f\).

On an unlabeled group, compute the veto rate given \(s_0\). Anchor a prior with Saerens EM if the judge-free score is calibrated on the source, otherwise with black-box shift estimation, and use a score that does not contain the judge. The anchor assumes \(P(s_0 \mid Y)\) does not depend on the group. Leave-one-country-out can falsify that where labels exist and cannot certify it for France. Reject constant likelihood if the observed veto rate lies outside the range of \(f_s\) and \(t_s\), or if it exceeds \(f_s \pi_{\text{anchor}} + (1 - \pi_{\text{anchor}})\). The second test needs no stable \(t_s\). It is the right check at \(p \ge 0.999\). If the group passes, and US–India leave-one-country agrees, set the odds after a veto to the anchor prior odds times \(f_s/t_s\). Equivalently, invert \(\pi\) from the veto rate itself and use \(f_s \hat\pi / r\). If that inverted prior and the anchor disagree beyond sampling error, the constant-likelihood assumption and the anchor cannot both be true. Do not average them. Do not clip in-country vetoes because France over-vetoes. The team measured that clip at a cost of **0.0005** to **0.0015** macro F0.5, which is what a small \(f_s\) predicts when the rare vetoes are informative. Whether the test US and India slices pass the check on these scores is unmeasured until the leave-one-country comparison is run. The higher decoy density makes a veto more decisive only by worsening the prior the same \(K\) multiplies.

If the group fails, which France does under any anchor near **0.999** at a **11.6%** veto rate, do not apply \(K_s\). With only \(t \in [0, 1]\) and the anchor, \(P(\text{match} \mid \text{veto})\) lies between \(1 - (1-\pi)/r\) and 1 when \(r \le \pi\). The lower end is the most a veto is allowed to move the probability. The operational point inside that interval that adds no unidentified France coefficient is the judge-free probability, not a France-only slope. Getting that probability by writing a missing judge into a stacker that saw the judge on every training row is a different estimator, and the team already measured it: masking the judge only at inference, on the orphan-refit stacker, dropped a dev score from **0.991** to **0.951**, while the same mask on a normally fit stacker went from **0.991** to **0.986**. Train-time dropout of the judge column would put a later mask on the support the tree actually fit; neural dropout is a training mask, not a fresh mask at inference, and tree-dropout methods that drop trees are not this mechanism ([Dropout](https://en.wikipedia.org/wiki/Dropout_(neural_networks)); [Rashmi and Gilad-Bachrach, AISTATS 2015](https://arxiv.org/abs/1505.01866)). That dropout stacker is in progress. It is not a finished upload, and neither is a stacker trained on India using scores from a US-only model. The only labelled reading of that US-only judge is that its India vetoes were all wrong, so fitting France's trust to those vetoes teaches over-rejection. Do not run the prior correction on a score that still contains the judge.

What unlabeled scores identify is the veto rate given \(s_0\), and whether that rate exceeds every constant-likelihood explanation of a chosen anchor. When the check passes and \(t_s\) is estimated from enough non-matches to be stable, they also identify the constant-likelihood posterior. What they do not identify is \(f\) and \(t\) separately on the unlabeled group, the Bayes factor, any France-only coefficient, the anchor itself unless \(P(s_0 \mid Y)\) is invariant, target calibration error, and the claim that a particular France veto is a true match. Setting \(t\) on France equal to \(t\) on the source identifies the factor and is not tested by the veto rate. A fully probabilistic middle, a prior on \(t\) averaged into a France coefficient, was not found as a published estimator for this stacker. Adding one would be an assumption, not a measurement.

## Pool the counts, and do not rank-normalise them

Recompute every split-size feature as a rate on the unlabelled records of the file being scored. Do not percentile-rank them, and do not drop name frequency or place IDF to make the adversary fail. The house-number relation is not a frequency feature. This fix does not touch it.

The standard weight is already a relative frequency. Inverse document frequency is \(\log(N/n)\) on the collection being scored, a function of the rate rather than of the raw count ([Robertson, Journal of Documentation 2004](https://doi.org/10.1108/00220410410560582); [Manning and Schütze, Foundations of Statistical Natural Language Processing, 1999](https://wiki.eecs.yorku.ca/course_archive/2014-15/W/6339/_media/chap15.pdf)). Fellegi–Sunter value-specific \(u\) is the same idea: \(u_i = f_i/T\) on the files being linked, estimated with no match labels, and a frequency table from another file is an approximation rather than the definition ([Winkler, Census RR2000/06](https://www.census.gov/content/dam/Census/library/working-papers/2000/adrm/rr2000-06.pdf); [Splink term-frequency guide](https://moj-analytical-services.github.io/splink/topic_guides/comparisons/term-frequency.html); [Christen, Febrl frequency weights](https://users.cecs.anu.edu.au/~Peter.Christen/Febrl/febrl-0.2.2/febrldoc-0.2.2/node34.html)). Rare agreement stays stronger evidence. That is the signal Newcombe's binit weights and Splink's term-frequency adjustment are built to keep ([Newcombe, American Journal of Human Genetics](https://pmc.ncbi.nlm.nih.gov/articles/PMC1706275/pdf/ajhg00393-0157.pdf)). Estimating the rate on a dev slice and freezing the numbers onto a larger test slice is the failure Manning and Schütze flag when a collection is assembled at scoring time, and the failure Winkler flags when one file is not a near subset of another.

For this batch, the collection is the strings that will be scored. Pool the unlabelled train and test strings if dev and test are one linkage, so the same token has one weight in both slices and a tree cannot separate the slices merely because each slice was divided by its own \(N\). If a slice is scored as its own linkage, estimate the rate on that slice. Fit the supervised matcher on labels after the table exists. Recompute the table inside each validation fold from that fold's own unlabelled rows, then again on the full file at the final pass. Otherwise a dev score whose frequencies included the validation rows is not an inductive risk on a future file. Using those unlabelled test strings is standard collection-frequency estimation. In Vapnik's sense it is transduction: the points to be labelled are already in hand, and the procedure is not required to ship a rule for a later file ([Transduction](https://en.wikipedia.org/wiki/Transduction_(machine_learning)); [Cortes and Mohri, NIPS 2006](https://papers.nips.cc/paper_files/paper/2006/file/639d79cc857a6c76c2723b7e014fccb0-Paper.pdf)). It is not label leakage. Leakage is use of the match bit. The inductive habit of freezing a train-only IDF vector is the wrong pipeline for a \(u\)-probability defined on the files being linked; the objection that train-plus-test IDF makes an offline score optimistic is an objection to quoting that score as performance on a future collection, which is a different claim ([Cross Validated, TF–IDF on train versus train+test](https://stats.stackexchange.com/questions/154660/tfidfvectorizer-should-it-be-used-on-train-only-or-traintest)). This contest forbids external data and lookups. It does not forbid the test strings that are the scoring collection. Do not import an outside frequency table.

Percentile or rank normalisation inside each slice forces each feature's marginal to match, so univariate adversarial separation on that feature falls to chance. No information-retrieval or record-linkage source found here recommends that as the fix for IDF or for frequency weights. It equates different absolute frequencies: a household of four can be a high percentile on a sparse slice and a middle percentile on a dense one, which erases a real change in \(u\). Dropping the features removes their contribution to adversarial AUC and also removes the frequency term the linkage weights treat as part of the match score. Drop one only if, once it is computed on the correct collection, it has no stable relation to matching. That relation was not re-measured here. Same-house count is not an IDF. People per address do not grow just because the file has more records, and they do grow if the extract is denser. Dividing that count by file size estimates the share of the file at that address, which is the right shape for a \(u\)-style weight and the wrong shape if the tree was using absolute household size. Recompute the count on the file being scored either way. Copying the dev household count onto test is the Winkler failure. Pooling removes the double-counting artifact. It does not remove a real difference in place mix or household density, and a token that is rare in the country can be useless once the candidates are the neighbours on one street, because the collection the weight refers to is the set being separated ([Linacre, address matching, 2025](https://www.robinlinacre.com/address_matching/)). Adversarial AUC near **0.88**, with gains on place-IDF sums and same-house counts as well as on the house-number relation, is larger than a pure sample-size effect. Pooled rates should cut the artifactual part and leave a residue. How large that residue is, on this feature set, is unmeasured. No source found ran percentile ranks, pooled rates, per-split rates, and dropping against an adversarial AUC. The house-number relation carried the largest team-reported adversarial gain, about **0.26**. Recomputing IDF does not move it.

What unlabeled strings identify is the collection rate of each token and the household count on the file being scored, and therefore a \(u\)-style weight that no longer depends on which slice was counted. What they do not identify is whether the remaining dev-versus-test separation is decision-relevant, the match rate of any pair, and the leaderboard effect of the recomputed features. That effect is unmeasured. The practical sequence is to recompute the rates, refit the adversary, and only then decide whether a weight is still worth estimating. Do not rank-normalise in order to watch AUC fall to chance and call the shift gone.

## A last-digit clash is three events, not one decoy

Do not label the extra test pairs as false, and do not delete them. Split "house number differs in the last digit" into comparison levels the postal sources already treat as different events, estimate each level's \(u\) by random sampling on the file being scored, and give the levels different weights. The **95%** labelled-dev match rate does not travel onto the unlabeled excess. The higher test prevalence does not identify the excess as decoys either.

A different primary number is a different delivery point in the address standards, not a fuzzy match. Linacre's worked non-match is Flat A, 24 Jubilee Street versus Flat A, 25 Jubilee Street, while a heavily rewritten pair that keeps building number 165 is a match; the rigid rule fails in production because messy addresses are hard to parse, not because adjacent numbers are the same site ([Linacre, 2025](https://www.robinlinacre.com/address_matching/)). A commercial quality note uses the neighbour case as the definition of a false positive that survives validation: the person at 2705 Champa Street who types 2707 has named a real delivery point, the neighbour, and a tool that accepts it has matched the wrong valid address ([Smarty, 2023](https://www.smarty.com/articles/address-false-positives)). USPS Publication 28 requires an exact match to the delivery file before a delivery-point code is assigned ([USPS Publication 28](https://pe.usps.com/cpim/ftp/pubs/pub28/pub28.pdf)). Census geospatial filtering keeps a candidate when the house number is the same and rejects it when the house number differs; the reported slide states that the house numbers should be the same ([Champney, FCSM 2024](https://statspolicy.gov/assets/fcsm/files/docs/2024-conference-docs/A/A2.2_Champney.pdf)). Those sources describe a mechanism. They do not label this team's unlabeled US pairs, and they do not overturn the **95%** figure inside the labelled confident slice, where the pattern can still be a one-character typo of a true match. No source found treats businesses at consecutive street numbers as duplicates.

Character edit distance and absolute numeric difference come apart, and a single "near house number" bucket hides the split. **12 versus 13**, and **120 versus 121**, are Levenshtein distance 1 and absolute difference 1: both a one-character substitution and a consecutive integer. **19 versus 20**, and **99 versus 100**, are absolute difference 1 and are not a one-character typo. **12 versus 22** is Levenshtein distance 1 and absolute difference 10: a one-character typo in a higher place, not the next integer. **12 versus 21** is a transposition. **12 versus 14** is absolute difference 2 and the same parity. Where US odd/even holds, a difference of 1 is opposite sides of the street and the next building on the same side is a difference of 2 or 4. Parity is built into ZIP+4's one-side segment and into local US standards, and it is not universal ([Esri, odd/even house-number matching](https://community.esri.com/t5/arcgis-pro-ideas/applying-odd-even-logic-when-matching-to-house/idi-p/1702478); [Edmunds GovTech, ZIP+4 and delivery-point codes](https://www.edmundsgovtech.com/zip4-and-dpc-explained/)). Jaro–Winkler on the numeral, the comparison used in at least one published address random forest, scores **12 versus 13** and **12 versus 22** as similar strings and does not know that **19 versus 20** is a numeric neighbour ([Comber and Arribas-Bel, Transactions in GIS 2019](https://onlinelibrary.wiley.com/doi/10.1111/tgis.12522)). Splink already documents the two level types, string edit distance and absolute numeric difference, as mutually exclusive comparisons evaluated in order. It does not publish them wired together with parity as a house-number recipe ([Splink comparison levels](https://moj-analytical-services.github.io/splink/topic_guides/comparisons/comparisons_and_comparison_levels.html)). The combination is the procedure, not a quoted library default.

The day's split, with no external address file, is five mutually exclusive levels. Exact primary number. Else a one-character edit whose absolute difference is not 1, the typo that is not the next integer. Else absolute difference 1, the consecutive integer, whether or not it is also a one-character edit. Else absolute difference 2 with the same parity. Else everything else. Estimate \(u\) for each level by random sampling of pairs from the file being scored, which is how Splink estimates \(u\) with no labels ([Splink Fellegi–Sunter guide](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html)). A higher test \(u\), with \(m\) held at the labelled value for that level, is a smaller match weight on test. That is evidence the pattern is less surprising among non-matches on that file, which is the decoy-mixture prediction. It still does not classify any one pair. Transporting a single dev \(m\), estimated on a pattern that was **95%** positive inside a confident subset, onto a test level dev barely contained, is the untested half. Do not join a ZIP+4 or delivery-point file to separate typos from real neighbours. That lookup is external data, which the rules forbid, even though it is the signature postal practice would have used.

Before interpreting **0.8%** versus **2.5%**, recompute both rates on all pairs with the pattern, not only on pairs the model already calls confident. If the gap exists only inside the confident set, the model is amplifying a pattern it learned, and the prevalence shift is not an independent fact about US addresses. That recomputation is unmeasured. The cross-tab of the labelled **95%** into the ambiguous cell (**12/13**) versus unambiguous typo cells (**12/22**, transpositions) is the measurement that would make a decoy reading of the excess decisive, and it is not reported. The leaderboard fall of about **0.00025** after adding about **15k** pairs is compatible with those pairs being net harmful, and it is also compatible with rank displacement or a small precision loss that is not "these pairs are false." It is not a label. Three stories fit the same counts: more genuine typo-duplicates of the kind dev rewarded, more true next-door firms, or the same mix admitted more often because training liked it. None of the label-free signatures authorises deleting the pairs. They authorise a different comparison level, with its own \(m\) and \(u\) on the file being scored, so that a one-character typo and a consecutive integer do not share one weight learned from dev.

What unlabeled test pairs identify is the mix of those five levels, the random-pair \(u\) of each level, and whether the **0.8%** to **2.5%** gap survives outside the confident set. What they do not identify is the match bit of any extra pair, the false-match rate of "near name, house differs by 1" on US streets (no published rate was found; the 2705/2707 and 24/25 cases are illustrations), and the share of the public gap those **15k** pairs explain. The effect of the five-level weight on macro F0.5 is unmeasured. Run the level split and the random-pair \(u\) before any upload that adds or removes neighbour-house matches. If the files do not differ on the levels, the sweep in the validation section has nothing to bite on, and a neighbour-house upload is not identified.

## One France upload drops source vocabulary, not the match rate

When the sign of the France error is not identified, any upload that reweights or re-thresholds from France's unlabeled marginal can help one indistinguishable problem and badly hurt another. The least harmful France-specific change is to turn off source-vocabulary features for France and to freeze the threshold at the worse leave-one-country macro F0.5. Do not spend the upload on France's match rate, an EM cutoff, a one-country rejector, test-set self-training, or a leaderboard probe.

France is **15%** of test Source 1 and has no labels. Copying the source mean of about **3.46** matches per reference, or the source singleton rate of about **5.6%**, is valid only under label shift: \(P(Y)\) moves, \(P(X \mid Y)\) does not ([Lipton, Wang, and Smola, ICML 2018](https://arxiv.org/abs/1802.03916); [Garg, Wu, Balakrishnan, and Lipton, NeurIPS 2020](https://arxiv.org/abs/2003.07554)). If France is harder than both labelled countries, the threshold that restores the source count sits at lower precision than it did on the source, and macro F0.5 prices that precision loss more heavily than a miss because \(\beta^2 = 0.25\). Quantile-matching the score histogram is the same idea one level down. In-domain temperature scaling does not stay calibrated under shift and can make error worse than no calibration ([Ovadia et al., NeurIPS 2019](https://ar5iv.labs.arxiv.org/html/1906.02530)). The team's reweighted-dev sketch that put France near **0.973** on the **0.985** file and near **0.965** on a later file is not a leaderboard number. It comes from a reweighting family that already failed to order the public files. Do not steer an upload toward it.

The classical unlabeled calibrator is the one the linkage literature warns against for error rates. Under conditional independence, EM estimates \(m\) and \(u\) with no labelled pairs, and those probabilities often do not match the truth at differing error rates ([Winkler, Census rrs2007-05](https://www.census.gov/content/dam/Census/library/working-papers/2007/adrm/rrs2007-05.pdf)). The likelihood-ratio rule can still rank pairs while the false-match curve is biased ([Tuoto, 2016](https://iris.uniroma1.it/retrieve/e383532e-502a-15e8-e053-a505fe0a3de9/Tuoto_New-proposal_2016.pdf)). Setting an F0.5 cutoff from that curve is the step that fails. Belin and Rubin's mixture was slightly conservative on average in simulations near their weight model; that average is not a guarantee for a new legal vocabulary, which is the regime where non-match weights move into the match region and a two-component fit understates false matches ([Belin and Rubin, JASA 1995](https://www.tandfonline.com/doi/abs/10.1080/01621459.1995.10476563)). EM on a single binary pattern can also sit on the boundary, with conditional probabilities at 0 or 1, because the likelihood is not strictly concave on a subspace of the log-odds ([Thibaudeau, WIREs Computational Statistics 2025](https://wires.onlinelibrary.wiley.com/doi/10.1002/wics.70015)). Conformal risk control bounds a loss that is monotone in the size of the prediction set, using labelled calibration data or a known covariate likelihood ratio ([Angelopoulos, Bates, Fisch, Lei, and Schuster](https://arxiv.org/abs/2208.02814); [Tibshirani, Barber, Candès, and Ramdas, NeurIPS 2019](https://arxiv.org/abs/1904.06019)). F0.5 is not monotone in the threshold: precision usually rises and recall falls. Prediction-powered inference needs a gold sample from the same population as the unlabeled sample, unless the shift is a known covariate or label shift ([Angelopoulos, Bates, Fannjiang, Jordan, and Zrnic](https://arxiv.org/abs/2301.09633)). US and India labels are the wrong population for a France interval. There is no scored clerical band. Mapping the uncertain band to non-link is the Fellegi–Sunter precision-first default, a tighter false-match bound than the false-nonmatch bound ([Shlomo, handbook chapter](https://library.oapen.org/bitstream/id/fb2e9e86-c2ea-484b-82cd-2597c78e2486/1007164.pdf)). Mapping it to link is the over-merge. An all-empty submission is not that default: a correct empty scores **1.0** only when the reference is truly a singleton, and an incorrect empty has recall 0, which zeros \(F_\beta\).

The conservative use of the labelled countries is a change of objective, not a France fit. Leave-one-domain-out as published maximises the average of the held-out domains, under the assumption that the test domain is another draw from the same meta-distribution ([Gulrajani and Lopez-Paz, ICLR 2021](https://ar5iv.labs.arxiv.org/html/2007.01434)). If France can be worse than every source, that average is optimistic relative to a country outside the convex hull of US and India difficulty. For a grid of thresholds, train without India and score India, train without the US and score the US, and take the threshold that maximises the minimum of the two macro F0.5 curves. Do not maximise the average. Do not take the stricter of the two univariate peaks. The team already found that a universal stricter threshold helps one direction and hurts the other. Those procedures differ: the easy direction can peak at a strict threshold whose recall cost the hard direction does not support, while the maximin stays where the worse curve still has support. It is allowed to sit between the two peaks. It is not "stricter than both." Inside a flat region of the minimum curve, prefer the higher threshold, and do not leave the flat region. A single noisy peak on the smaller country is a winner's curse; the threshold that wins on one finite fold can sit on the wrong side of the grid with a probability that does not shrink until \(n\) is very large ([Lipton, Elkan, and Naryanaswamy, ECML PKDD 2014](https://pmc.ncbi.nlm.nih.gov/articles/PMC4442797/)). The resulting minimum estimates transfer between these two countries. The team's leave-one-country stage-2 loss of **0.005** to **0.019** macro F0.5, mostly precision, is a lower illustration of a country shift that still shares more lexical material than France. It is not an upper bound on the France drop. No learner that sees only source labels and target inputs can guarantee the harder domain, and reweighting source rows by the target covariate density can help one task and cause dramatic deterioration on another task the learner cannot tell apart ([Ben-David, Lu, Luu, and Pál, AISTATS 2010](https://proceedings.mlr.press/v9/david10a.html)). After the maximin threshold is fixed, do not move it so that unlabeled France has mean degree **3.46** or an empty rate of **5.6%**. Group DRO is a training objective on groups it can see. France is not one of those groups, and it does not supply a threshold ([Sagawa et al., ICLR 2020](https://arxiv.org/abs/1911.08731)).

The feature half of the upload is the part that does not require knowing the sign. France-versus-France pairs are not a translation problem. Both sides use French street words and legal forms the US and India tables never listed. A feature survives if it scores two French strings from their own characters. Levenshtein and plain Jaro do. Character n-grams do, and they need no stemmer and no suffix list ([Mayfield and McNamee, SIGIR 2003](https://dl.acm.org/doi/10.1145/860435.860528)). Exact equality of the house-number token does, because digits are not a Romance vocabulary ([Winkler, Census rrs2007-05](https://www.census.gov/content/dam/Census/library/working-papers/2007/adrm/rrs2007-05.pdf)). Order-free token overlap does, so a house number that moved to the other end of the string still agrees. Word IDF fit on US and India does not. An unseen French token has document frequency 0. Implementations then drop it, which deletes the only evidence that two French names share a content word, or give it maximum IDF, which over-weights an accidental shared function word or a shared legal form. Soft TF–IDF inherits that table; only the Jaro piece is lexicon-free, and Cohen's TF–IDF result was on in-language name lists whose IDF corpus matched the names being scored ([Cohen, Ravikumar, and Fienberg, IIWeb 2003](https://www.cs.cmu.edu/~wcohen/postscript/kdd-2003-match-ws.pdf)). A closed English legal-form list will not strip SARL, SAS, SA, or EURL. Residual suffixes look like name disagreements. Building a French list is an external lexicon, which the rules forbid. Deleting the English list, rather than translating it, is the allowed move. Jaro–Winkler's prefix bonus is not a lexicon, and it was designed for shared surname prefixes. Many French addresses share a short function-word prefix. Prefer plain Jaro, character n-grams, or a house-number gate. That preference is a mechanism argument, not a French experiment. No paper found measures these features on French business names under macro F0.5 with US and India training only. Cross-lingual product matching is a different task, uses target-language labels or external web identifiers in the results that were actually discussed, and is not a France F0.5 target. An English-only encoder fine-tuned on German lost to a lexical SVM, and extra English pairs did not help that SVM ([Peeters and Bizer, WWW Companion 2022](https://arxiv.org/abs/2110.03338)). Do not quote those product F1 figures as an achievable France score.

Same-address, one-word descriptor swaps are true matches on **99.99%** of labelled dev pairs. A feature or a judge that treats one leftover token as strong negative evidence rejects true pairs that differ by a legal form or a descriptor. That is the argument for house-number equality plus a soft character comparison, and against an English suffix list that leaves a French suffix in place. It is not an argument for lowering the France threshold to the source match rate. The upload, France only, is: drop word IDF learned on US and India, drop English legal-suffix deletion, score name and street with character n-grams, Levenshtein or plain Jaro, token-set overlap, and exact house-number equality, and ship the maximin threshold. Pick the n-gram order on US and India macro F0.5 and freeze it. Do not pick it on France. Do not lower the threshold to chase France's raw score mass, and do not raise it past both source curves. Leave the US and India production path on the current **0.985** file unless the maximin threshold was already that file's selection rule. A global retune selected on dev is how the later files lost the public board. The swap can still hurt if character n-grams collide more in French than in the source countries. That collision rate is unmeasured. Both directions of the feature choice on the labelled countries are measurable before the upload. The effect on France is not. The swap cannot silently implement a France prior, which is the property the marginal-matching uploads do not have.

Do not spend a second upload on the paths that already failed or that the rules close. Clipping in-country vetoes costs accuracy. A LoRA trained only on the previous model's mistakes reached AUC **0.21** on the team's check; the published analogue is an in-domain gain and a cross-domain loss of about **12** F1 when a model is specialised on neighbours of its own errors ([fine-tuning study](https://arxiv.org/html/2409.08185v1)). Self-training on the unlabeled country is out of bounds: the team's leave-one-country proxy gained on one round and then lost the gain to a recall collapse, and an unlabeled pseudo-label step is another estimator of the kind that is biased when the country is harder. Oracle selection on the test domain is not a valid model-selection method even when the number of test queries is capped ([Gulrajani and Lopez-Paz, ICLR 2021](https://ar5iv.labs.arxiv.org/html/2007.01434)).

What unlabeled France inputs identify is the marginal veto rate, the score histogram, the character strings needed for lexicon-free comparisons and for a collection-frequency table, and the failure of a constant \((f, t)\) against an anchor one is willing to assume. What they do not identify is the F0.5-maximising threshold, the sign of over-merge versus over-reject, a France class prior, a calibrated France posterior, and the size of the drop beyond the **0.005** to **0.019** US–India transfer loss. The maximin number is a constraint on the labelled transfers. It is not a lower bound for France.

## Conclusion

The failed uploads are one identification error counted several ways. Reweighting, orphan simulation, a stricter universal threshold, clipping in-country vetoes, and an inference-time mask each change a parameter unlabeled data do not pin, then trust a dev functional that has already pointed the wrong direction by a few ten-thousandths. The objects that are pinned are narrower, and they are worth computing before any file is sent: a collection rate that no longer depends on slice size, a random-pair \(u\) for each house-number level, a veto rate that can reject a constant likelihood, and a threshold that is only a constraint on transfer between the US and India. An upload that changes one of those objects can be wrong and still be checked on labelled countries first. An upload that changes France's match rate, the judge's slope, or a synthetic non-match rate until **0.985** sits on top cannot be checked at all.

France at **15%** of test Source 1 makes a confident false merge expensive under macro F0.5, and the same arithmetic makes a **0.999** veto illegal once **11.6%** of those pairs are vetoed and the anchor is taken at face value. Those two facts point at different knobs. The vocabulary features and the house-number levels are the knobs unlabeled strings can turn. The judge's coefficient is not. Hold the **0.985** file as the control, change France's source-vocabulary features and the neighbour-house comparison levels only after the labelled-country checks and the random-pair \(u\) are in hand, and leave the unfinished dropout stacker and the India-scored-by-US stacker off the upload list.
