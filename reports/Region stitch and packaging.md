# Score two region edits before stitching

Upload **A** and **B**, and nothing else, before **27 Sep 2026 23:59**. **U1** stays the file of record at public macro F0.5 **0.985** (dev **0.99030**) until a pre-registered edit beats that public number. **A** copies **U2**’s decisions onto every Source 1 entity whose country string appears with a training label and leaves every other entity as **U1**, which asks whether the extra pair features help the labelled countries once **U2**’s drop of about **5–10k** unlabelled-country pairs is removed. **B** leaves labelled-country entities as **U1** and adds back **8,506** pairs in countries with no training labels, undoing a judge veto only where the stage-2 score is already **≥ 0.99**, with each Source 2/3 record kept for at most one Source 1. If both public scores beat **0.985**, designate the entity-wise stitch of those two edits; its public score is **S(A) + S(B) − S(U1)** when the one-to-one check on the union is clean, and that identity is not a third experiment. If one beats **0.985**, designate that file. If neither does, keep **U1**. No label-free method identifies the judge’s new error rates, the constant-likelihood prior correction stays closed, and a neighbour-house deletion is not an upload: on labelled dev a confident off-by-one pair is a match **96.3%** of the time.

## The stitch is the sum of two region lifts, not a blend of two files

Macro F0.5 here is the unweighted mean of per-Source-1 scores, the same kind of object as an averaged F rather than an F of averaged precision and recall ([Opitz and Burst, arXiv:1911.03347](https://arxiv.org/abs/1911.03347); [A Closer Look at Classification Evaluation Metrics, TACL](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00675/122720/A-Closer-Look-at-Classification-Evaluation-Metrics)). Inside one entity the score is a nonlinear function of that entity’s true positives, false positives, and false negatives, and **β = 0.5** weights precision more than F1 does. Across entities the outer mean is linear. A correct empty set scores **1.0**. That is not the convention that sets an undefined F to 0 ([Opitz and Burst](https://arxiv.org/abs/1911.03347)).

Let **A** differ from **U1** only on entities whose country is in the training-label set, and let **B** differ only on entities whose country is outside it. Copy each entity’s entire predicted set from one parent, including the empty set. On any slice that scores whole entities, the stitch score is exactly **S(A) + S(B) − S(U1)**. Each entity is counted once. Averaging **S(A)** and **S(B)**, or adding both lifts on top of the better file, counts the shared baseline twice. A weight times **S(A)** plus a weight times **S(B)** is also the wrong mixture: each file’s overall score still contains the region the stitch was supposed to throw away. The legal weights, if the score is written as a mixture at all, are shares of Source 1 entities inside each region, not pair shares and not equal country weights. The unlabelled country is **15%** of test Source 1, so on the full file its entity weight is **0.15**. The **8,506** pairs do not say that. A country with many pairs and few references is a small term in macro F0.5 and a large term in a row-weighted blend. Those are different scores.

There is no principled combiner beyond that entity partition. Averaging the two files’ probabilities and re-thresholding builds a hybrid positive set whose F0.5 equals neither parent, because a ratio is not a weighted mean of ratios. Taking one F0.5 from the two files’ global precision and recall is the other Opitz formula, and that formula can reverse a ranking ([Opitz and Burst](https://arxiv.org/abs/1911.03347)). A global one-to-one re-solve is a third policy. Fellegi–Sunter classifies pairs independently and can link one record to many; a maximum one-to-one assignment is a later constraint used when each file is assumed free of duplicates ([Jaro, JASA 1989](https://www.tandfonline.com/doi/abs/10.1080/01621459.1989.10478785); [R Journal 2019-008](https://journal.r-project.org/articles/RJ-2019-008/RJ-2019-008.pdf)). Febrl extracts connected components and solves them with an auction algorithm precisely because a greedy pass is not that optimum ([Christen, Febrl one-to-one notes](https://users.cecs.anu.edu.au/~Peter.Christen/Febrl/febrl-0.3/febrldoc-0.3/node67.html)). Gold matches never cross countries. Predictions can. If **A** assigns a Source 2/3 id to a labelled-country reference and **B** assigns the same id to an unlabelled-country reference, each parent can still obey “at most one owner” and the union does not. Scored independently, the double claim is just an error inside each entity and the macro sum still adds. Relative to the task constraint the file is illegal. If the scorer drops one edge or re-solves the component, at least one entity’s set is no longer the parent’s set and the sum identity is void.

The same break happens if the merge is “use **U2** when both files scored the candidate, otherwise keep **U1**,” if row numbers are aligned across files of different lengths, or if a concatenation is used in place of a set copy. Concatenation keeps pairs the new file had removed and double-inserts pairs present in both. An entity with a correct empty set has no rows. A row overwrite does not delete the other file’s pairs, so the stitch silently unions, and under the **1.0** empty rule that entity moves the macro by a full **1/N**.

Under the identity, the planned accept rule is the right one, and it is sharper than “stitch whenever the sum beats **0.985**.” The stitch’s lift is the sum of the two region lifts. It beats the better single edit only when both lifts are positive. If one region’s public delta is negative, folding it in makes the stitch worse than the winner alone. Shipping both only when each beats **0.985** includes a region exactly when its own lift is positive. It does not require a third model, and it is not eight country tilings. Looking at per-country public contributions and then assigning each country to whichever parent won would be that larger search. Do not retile after the scores return.

The public number of a file chosen before any score is seen is an unbiased estimate of that file, up to split noise ([Blum and Hardt, arXiv:1502.04585](https://arxiv.org/abs/1502.04585)). The rule “ship whichever of **A**, **B**, and the stitch cleared **0.985**” still picks after seeing the public slice. The same slice both selects and is then quoted as the performance of the selection ([Tibshirani and Tibshirani, Annals of Applied Statistics 2009](https://arxiv.org/abs/0908.2904)). That is the winner’s curse: the estimate at the chosen point is biased high, and it shrinks on a fresh sample ([PLOS Genetics 2023, winner’s-curse review](https://journals.plos.org/plosgenetics/article?id=10.1371/journal.pgen.1010546)). For two variants with the same true score and independent public noise of standard deviation **σ**, the expected public score of the winner sits **σ/√π ≈ 0.56σ** above the common mean ([half-normal distribution](https://en.wikipedia.org/wiki/Half-normal_distribution); [maximum of two standard normals](https://math.stackexchange.com/questions/4527964/maximum-of-two-standard-normal-distribution)). A single pre-registered contrast with true effect zero, shipped only when the public delta is positive, has conditional expected public delta **σ√(2/π) ≈ 0.80** times the standard error of that delta. When the two files agree on most entities, correlation **ρ** replaces that gap with **σ√((1−ρ)/π)**. The standard error that matters is the standard error of the region delta, not the standard error of the whole-file macro. These factors are Gaussian order statistics. They are not a shake probability, and they cannot be turned into macro-F0.5 points, because that standard error was not estimated and cannot be read off **0.985**.

On a complementary half, and only if every scored entity lies wholly in public or wholly in private, public luck is private un-luck of the same size: **S_priv = 2 S_full − S_pub**. If the true delta is zero, the expected private delta given a positive public delta is about **−0.80** times the public-delta standard error. That sign flip is an expectation under a zero effect, not a forecast that this private score will fall. It dies if the organiser’s split cuts inside entities, because public F0.5 and private F0.5 of one entity are not linear pieces of that entity’s full F0.5. The split unit and the public country mix are unpublished, so a public delta cannot be divided by **0.15** to recover an unlabelled-country effect, and neither the **0.80** standard-error story nor any other numeric shake chance is available. A classification-accuracy meta-analysis in which public and private gaps were typically under about one percentage point is the wrong yardstick ([Roelofs et al., NeurIPS 2019](https://papers.nips.cc/paper/9117-a-meta-analysis-of-overfitting-in-machine-learning)). Drops of about **4–10%** on a fresh CIFAR-10 draw and **11–14%** on a fresh ImageNet draw are a new sample, not a random split of one file ([Recht et al., arXiv:1806.00451](https://arxiv.org/abs/1806.00451); [Recht et al., ICML 2019](https://proceedings.mlr.press/v97/recht19a.html)). Do not import them as a prior for this private board.

Named segment blends have gone both ways, and both clean cases are time splits. A per-site model in ASHRAE was reported useful because sites did not share one parameter set, and that team moved from **12th** on the public board to **2nd** on the private board, while also setting some ensemble weights from the public score and inserting leaked rows ([cha0s, ASHRAE 2nd-place write-up](https://www.kaggle.com/competitions/ashrae-energy-prediction/writeups/cha0s-2nd-place-solution)). Country multipliers probed on the public slice of Forecasting Mini-Course Sales, Argentina **4.5**, Spain **1.6**, Japan **1.2**, Estonia **1.7**, Canada **0.9**, scored public SMAPE **6.08955** and private **7.21200**, lower better, while a mean of strong public submissions still reached **17th** private ([Kowalczyk write-up](https://www.kaggle.com/competitions/playground-series-s3e19/writeups/mateusz-kowalczyk-blending-best-public-submissions)). The private slice of that contest was the last **75%** of 2022, not a random half ([Albert Zhang, 3rd-place write-up](https://www.kaggle.com/competitions/playground-series-s3e19/writeups/albert-zhang-3rd-place-solution-eda-is-the-key)). Nothing found is an entity-resolution contest on macro F0.5 in which a country stitch of two match files was compared with a global blend on a random split. Importing **6.09 → 7.21**, or **12th → 2nd**, as this contest’s gap would invent a result. The lesson that does transfer is narrower: do not tune a country multiplier, or the **0.99** cutoff, on the public score after **A** and **B** return.

Before the stitch is treated as scored, check the files locally. Key rows as pairs, not line numbers. Confirm that the symmetric difference of **A** against **U1** touches only reference ids whose country is in the training-label set, and that **B** against **U1** touches only reference ids outside it, counting deletions as well as additions. Build the stitch by entity: labelled-country sets equal **A**, unlabelled-country sets equal **B**, every other set equal to **U1**, empties included. Map each Source 2/3 id to the Source 1 ids that claim it. Any id with two owners is a conflict the parents could not see. If that set is empty, the public score of the stitch is the sum identity, and quoting it beside **S(A)** and **S(B)** as three independent runs double-counts one slice. If it is not empty, do not use the identity. Resolve inside each connected component by a rule fixed now: higher stage-2 probability, then lexicographic reference id. Record every reference whose set changed. Each such entity moves the macro by at most **1/N**, with **F0.5** inside **[0, 1]**. If the touched-entity share is not smaller than the inferred lift, the inferred public score is not a score, and the repaired file is a new submission. **U2**’s public **0.98475** and **U3**’s **0.98476** already lost to **U1** after dev gains, including **U2**’s dev **0.99079**. Those full-file losses do not answer **A**. **U2** follows the judge less often than **U1** on the labelled countries, emits about **16k** more US pairs the judge vetoes and about **16k** more US house-mismatch pairs, and also emits about **5–10k** fewer pairs in the unlabelled country. The two **16k** counts must not be added; they may be the same pairs. **A** removes the unlabelled-country confound. It does not remove the labelled-country override.

## A single veto rate can reject the old judge and still leave the new one unnamed

One veto bit inside a bin of a judge-free score has rate **r = fπ + t(1−π)**, with **f** the false-veto rate on matches, **t** the true-veto rate on non-matches, and **π** the match prior in the bin. Given only **r**, the identified set of **f**, of **t**, and of **π** is all of **[0, 1]**. The only sharp fact with no extra assumption is joint: **min(f, t) ≤ r ≤ max(f, t)**. For any candidate **f₀** the triple **(f₀, r, 0)** matches **r**; for any **t₀**, **(r, t₀, 1)** matches **r**. A rate above the dev value of **t** rejects frozen **(f, t)**, including by a negative implied prior. It does not force **t** to have risen. The triple **(r, t₀, 1)** reproduces the new rate with **t** left unchanged, which is the story that the bin is all matches and every veto is a false veto. Concluding that **t** rose requires a restriction the test rate does not identify, either **f ≤ t** or a cap **f ≤ f̄ < r** ([Horowitz and Manski, Econometrica 1995](https://www.jstor.org/stable/2951627); [Manski, identification monograph excerpt](https://ebin.pub/identification-problems-in-the-social-sciences-9780674265790.html); [Molinari, Journal of Econometrics 2008](https://www.sciencedirect.com/science/article/abs/pii/S0304407607002564)). Stronger assumptions narrow the set and are less credible ([Imai notes on Manski 2007](https://imai.fas.harvard.edu/teaching/files/bounds.pdf)).

The closed measurements are already that rejection. Leave-one-country inversion, freezing **(f, t)** from one labelled country and inverting the other’s rate, fails for judge-free score **s₀ < 0.8**: implied priors run from **−0.42** to **−1.53** against labelled truth **0.03–0.32**. It roughly tracks at **s₀ ≥ 0.8**, for example an inverted prior **0.967** against truth **0.976** in one such bin. That track does not validate **t**. When **π** is near 1, **r** is near **f** and barely depends on **t**. An illustration, not a refit: **f = 0.01**, **π = 0.97**, **t = 0.70** gives **r = 0.0307**; inverting with the wrong **t = 0.40** returns **π ≈ 0.947**. The informative failure is the one below **0.8**, where **r** is driven by **t**. Across the labelled countries **f** sits in about **0.005–0.027** and **t** does not: about **0.37–0.50** in the US and **0.60–0.76** in India. At **s₀ ≥ 0.999** there are only **15–19** labelled non-matches, so **t** in the top bin is almost unidentified.

On test, the veto rate is impossible under dev **(f, t)** in every middle bin, in all three countries. The US rates are **0.72 / 0.60 / 0.21** in bins **0.5–0.8 / 0.8–0.95 / 0.95–0.99**, against dev rates about **0.10 / 0.09 / 0.03**. Only the US and India at **s₀ ≥ 0.999** match dev, at about **0.0009–0.0011**. The unlabelled country in that same nominal bin is **0.049**. Matching a single **r** is not matching **(f, t)**: every triple on the fiber of that **r** fits, and dev **t** at the top rests on those **15–19** non-matches. The unlabelled country’s **0.049** does not by itself reject a shared top-bin **(f, t)** with dev, because two rates may both lie between **f** and **t**, and whether **0.049** is above dev **t** in that bin is unmeasured. It does reject reading the unlabelled top bin as the same rare veto as **0.001**. Negative implied priors are a specification test of constant **(f, t)**. They are not an estimate of the new prior. Clipping them to 0, the patch black-box shift estimation uses so that a weighted risk stays bounded, would invent “all non-matches” and is not an identified value ([Lipton, Wang, and Smola, ICML 2018](https://arxiv.org/abs/1802.03916); [BBSE negative-weight clip](https://assets.amazon.science/53/21/14143d6c4ecbb9b1ccdbd71162bd/detecting-and-correcting-for-label-shift-with-black-box-predictors.pdf)).

No method in the standard list point-identifies **t** once both **π** and **(f, t)** can move. **B** bins give **B** equations and **3B** unknowns. Three countries with their own parameters give **3B** equations and **9B** unknowns. A monotone score does not cut the set to a point. Constant **(f, t)** across bins is the model dev already rejected below **0.8**, and it becomes a point only with a pure non-match anchor and a pure match anchor, which is weak separability of the corrupted posterior ([Menon, van Rooyen, Ong, and Williamson, ICML 2015](https://proceedings.mlr.press/v37/menon15.html); [Scott, Blanchard, and colleagues, arXiv:1303.1208](https://arxiv.org/abs/1303.1208)). The top bin is where matches concentrate, not a pure non-match bin. Black-box label shift and its likelihood-ratio cousins are consistent only when the confusion matrix is invariant ([Lipton, Wang, and Smola](https://arxiv.org/abs/1802.03916); [Garg, Wu, Balakrishnan, and Lipton, NeurIPS 2020](https://arxiv.org/abs/2003.07554)). A 2026 label-shift estimator still states the assumption as no concept drift ([Zhang, Batista, and Kanhere, arXiv:2604.01651](https://arxiv.org/html/2604.01651v1)). Finite mixtures of binomials are not identifiable; a thresholded bit is in that family ([Yakowitz and Spragins, 1968](http://dml.mathdoc.fr/item/1177698520); [Teicher, 1963](https://doi.org/10.1214/aoms/1177703862)). A **t** that changes with the score bin is instance-dependent noise, which is unidentifiable from noisy labels alone ([Xia, Liu, Han, and colleagues, NeurIPS 2020](https://arxiv.org/pdf/2006.07836)). EM does not create identification the likelihood does not have. The likelihood of one bit depends on the data only through **r**, so every triple on the fiber has the same likelihood. Winkler’s unsupervised EM needs redundant fields, a match proportion that is not tiny, separation, and a conditional-independence fit that is actually useful, and the latent classes need not be the match and non-match classes the user named. The same **m** and **u** “can vary substantially from an urban region to an adjacent suburban region” ([Winkler, JSM 2002](http://www.asasrms.org/Proceedings/y2002/Files/JSM2002-000648.pdf)). Two binary experts on the same pairs are still short. Three conditionally independent experts are the smallest generically identifiable case, and only up to a label swap that an ordering **f < t** can break ([Allman, Matias, and Rhodes, Annals of Statistics 2009](https://arxiv.org/abs/0809.5032)). Three countries are three separate mixtures, not three raters on the same pairs. A mass of known non-matches identifies **t** only for the distribution those non-matches were drawn from. Random-pair **u**, the usual label-free estimate, targets easy chance pairs, not non-matches that landed in a high-score bin ([Splink Fellegi–Sunter guide](https://moj-analytical-services.github.io/splink/topic_guides/theory/fellegi_sunter.html)). Dev already shows why the slice matters: high-bin **t** differs between the two labelled countries.

The leaderboard is the only arbiter of whether a policy raises macro F0.5. It does not point-identify **t**, and it is not needed to reject dev-calibrated use of the veto. Do not spend an upload on Saerens EM, black-box shift estimation, a maximum-likelihood label shift, or a clipped negative prior. Those are the constant-likelihood update the labelled inversion already falsified. Train-time dropout of the judge is a closed negative as well: with the judge present at scoring, dev macro F0.5 is **0.99028** against **0.99029**. Masking the judge only at inference costs about **0.004–0.005** on a normally fit stacker. The earlier collapse from **0.991** to **0.951** was the orphan-refit stacker only. **B** has to stay a decision-layer add-back on countries outside the training-label set. It is not a refit that drops the judge column, and it is not a new coefficient on the veto.

What remains, before any upload, is a sensitivity bound under one explicit cap. Maintain **f ≤ 0.027**, the top of the labelled range, not a confidence interval and not a test measurement. Then **t ≥ r** whenever **r** exceeds the cap, and the share of vetoes that are matches has a sharp upper bound **f̄(1−r) / (r(1−f̄))**. On the US test rates that bound says the veto is a reliable rejector: at **r = 0.72**, **t ≥ 0.72**, **π ≤ 0.288**, and at most **1.1%** of vetoes are matches; at **r = 0.60**, at most **1.8%**; at **r = 0.21**, at most **10.4%**. The same cap says the opposite where the rate is low. At **r ≈ 0.001** the cap does not bind, a veto can be always right or always wrong, and the only assumption-free statement is exposure: the fraction of the bin that is both a match and vetoed is at most about **0.001**. At the unlabelled country’s **r = 0.049**, **t ≥ 0.049** and **π ≤ 0.977**, but up to **53.9%** of vetoes can be matches. Dropping the cap reverses the high-rate reading, because **f = r** and **π = 1** is always inside the identified set. The cap is more plausible than a cap on **t**, because **f** was the stable labelled quantity and **t** was not. Two countries are a thin base. Test **f** is unmeasured. Manski’s law applies: using the cap on test is an extrapolation, not an identification.

That split is why **B** is the upload the bound does not settle, and why **A** is still worth its slot even though the bound dislikes overriding a high-rate veto. **B** undoes vetoes only at stage-2 **p ≥ 0.99**, the region where the unlabelled top bin is **0.049** and the cap does not make the veto a supported hard reject. It does not undo the middle bins, where the US rates are high and, under the cap, the veto is mostly a true reject. **A** imports **U2**’s labelled-country overrides, including the extra judge-vetoed US pairs. Under the cap those middle-bin vetoes should stand. The cap is not identified on test, dev already preferred **U2** (**0.99079** against **0.99030**), and every dev gain after **U1** has failed on the public board, so dev cannot rank **A**. The public loss of full **U2** is confounded by the unlabelled-country pair drop. One upload is the comparison that removes the confound. It still returns one number for one policy. A higher score does not isolate which of **f**, **t**, and **π** moved. Without the cap, no bin has a reliability lower bound, exposure is the only pre-upload bound, and the leaderboard is the only arbiter of whether turning the veto off helps. In that case the upload still will not reveal **t**.

## Keep the neighbour: a 0.963 match is the duplicate, not the decoy

Published systems score exact house agreement as a stronger pairwise level than a numeric or edit difference. They do not state the decision rule “if one query has both an exact house candidate and a neighbouring-number candidate, delete the neighbour.” Splink’s comparison levels set one gamma on one pair. A waterfall can be exact, then a weaker similarity, then everything else, and both pairs can stay above a threshold ([Splink comparison levels](https://moj-analytical-services.github.io/splink/topic_guides/comparisons/comparisons_and_comparison_levels.html); [Splink level library](https://moj-analytical-services.github.io/splink/api_docs/comparison_level_library.html)). One-result geocoders return a single best address and flag a neighbour only as a fallback when the requested number is absent. HERE sets **houseNumberFallback** in that missing-number case and tells the caller what numeric gap is acceptable; it does not delete a second record when the exact number is present ([HERE house-number fallback](https://www.here.com/docs/bundle/geocoding-and-search-api-developer-guide/page/topics-api/code-geocode-hsn-fallback.html)). USPS Delivery Point Validation confirms the primary number that was submitted. Footnote M3 means that number is invalid. The documented primary-number exception drops one trailing letter so that 123B can confirm as 123. It does not rewrite 19 as 20 ([USPS Publication 28](https://pe.usps.com/cpim/ftp/pubs/pub28/pub28.pdf); [USPS ZIP+4 range logic](https://pe.usps.com/text/pub28/28ape_003.htm)). The place the second candidate is discarded is one-to-one linkage of files assumed to contain no duplicates, or a geocoder that wants one canonical address ([Sadinle, arXiv:1601.06630](https://arxiv.org/pdf/1601.06630); [Linacre, address matching, 2025](https://www.robinlinacre.com/address_matching/)). Linacre’s canonical non-match is Flat A, 24 Jubilee Street versus Flat A, 25 Jubilee Street, and he also rejects the hard rule “different building number means non-match,” because a bad parse then drops true matches. Splink clusters duplicates with connected components precisely because one entity has many non-identical copies. Keeping only one of two definite matches can delete the only path to a third true duplicate ([Splink issue #1231](https://github.com/moj-analytical-services/splink/issues/1231); [Splink deduplication case study](https://realworlddatascience.net/applied-insights/case-studies/posts/2023/11/22/splink.html)).

This task is the multi-copy problem. A Source 1 business matches several Source 2/3 records, mean about **3.46**. On US dev, among stage-2 pairs with **p ≥ 0.5**, a house number that differs by 1 is **0.45%** of pairs and a labelled match **96.3%** of the time. A same-parity difference of 2 is **0.48%** of pairs and a match **95.6%** of the time. A one-character typo that is not the neighbour pattern is **4.6%** of pairs and a match **98.7%** of the time. India barely changes. “Keep only the best-addressed candidate” treats the exact record and the neighbour as mutually exclusive answers to one query. In the typical labelled case the neighbour is a true typo-duplicate. Dropping the entire off-by-one slice would remove about **0.433%** of confident pairs that are labelled matches and about **0.0167%** that are labelled non-matches, roughly **26** true pairs per false pair. The same-parity off-by-two slice is about **22** true pairs per false pair. Those ratios are marginal upper bounds. The rule fires only when a better-addressed sibling exists, and the labelled match rate conditional on an exact-house, same-name co-candidate was not measured. Two effects push that conditional rate in opposite directions: the neighbour may be a different door once the exact record is present, or the exact copy and the one-digit typo may co-occur because duplicates are common. Which effect wins is not in the marginal table. Using **0.963** as if it were the conditional rate cannot be signed.

The test excess is not a substitute for that cross-tab. Inside **p ≥ 0.5**, US off-by-one rises from **0.45%** to **1.14%**, about **2.5×**, and same-parity off-by-two from **0.48%** to **1.16%**. The non-neighbour one-character share rises only from **4.6%** to **5.2%**. All-candidate shares rise less, **0.47%** to **0.77%** for off-by-one. The shift is US-specific and concentrated in the confident neighbour levels. Where US parity is coded, a difference of 1 is typically across the street and a same-parity difference of 2 is the next number on the same side ([TIGER/Line Chapter 4](https://www2.census.gov/geo/pdfs/maps-data/data/tiger/tgrshp2009/TGRSHP09C4.pdf); [Esri parity matching](https://community.esri.com/t5/arcgis-pro-ideas/applying-odd-even-logic-when-matching-to-house/idi-p/1702478)). That pattern is compatible with more true adjacent businesses, more numeric typos, or more non-matches. The test match bit is unknown. Fitting a drop rule to explain the rise would, on dev, aim at a slice that is **96%** labelled matches. A one-character substitution such as 12 versus 13 is both a difference of 1 and an edit. 19 versus 20 is a difference of 1 and Levenshtein distance 2. The **0.963** bucket mixes them. Any rule that treats every Levenshtein-1 house string as a neighbour also touches the **4.6%** cell whose labelled match rate is **0.987**, which multiplies the recall damage.

A slice whose labelled match rate is **0.963** raises precision only when operating precision of the **p ≥ 0.5** set is already above **0.963**. That operating precision was not supplied, so a precision gain is not established. Under F0.5, removing **26** true pairs to remove one false pair is still a recall-dominated change. Macro F0.5 then averages across entities, so a slice under half a percent of confident pairs can move the headline by very little while deleting most of the typo-duplicates of the businesses that have them. The public gap from **U1** at **0.985** to **U2** at **0.98475** is **0.00025**. That is the order of movement a slice this small produces, and one F-measure value is compatible with very different precision and recall mixes ([Hand and Christen, JDIQ](https://dl.acm.org/doi/10.1145/3786768)). The **0.00025** does not label the extra house-mismatch pairs, and the judge is not a gold label. **U1** follows the judge on the labelled countries. **U2** overrides it. Those overrides are what **A** tests. They are not a reason to delete neighbours inside **U1**.

No published result suppressed adjacent house numbers, raised a precision-heavy F, and stated the recall cost in true pairs lost. The closest census experiment runs the other way. Brummet’s baseline blocks on ZIP and the full house number, because “120 RED RIDGE RD” and “121 RED RIDGE RD” are “certainly different housing units,” and the match rate on one state is **78.14%** of **5,325** survey addresses. On a second state, allowing “213 MAIN ST” to match “215 MAIN ST” moves the match rate from **75.83%** to **90.54%**, **+14.71** percentage points, and he writes that the vast majority of the new matches come from the house-number relaxation. He also writes that the false-match rate cannot be known without truth data ([Brummet, CARRA WP 2015-04](https://www.census.gov/content/dam/Census/library/working-papers/2015/adrm/carra-wp-2015-04.pdf)). His match rate is the fraction of queries that received a link, under a one-address-to-one-unit assignment. Dropping 203 once 201 is present loses nothing if 203 is a different unit. Here it loses a true duplicate whenever both records are the same business. At the strict end of his first table, allowing neighbours while keeping a high cutoff buys well under one percentage point, and the large gains appear only after the cutoff is low enough to accept 40 versus 41 and 201 versus 203. Confident pairs that are labelled matches **96%** of the time are not in that low-cutoff regime. Geocoding papers that tighten the house number report lower match rates and, when they measure it, smaller positional error. They do not report linkage F0.5 ([Cayo and Talbot, 2003](https://ij-healthgeographics.biomedcentral.com/articles/10.1186/1476-072X-2-10)).

The decision-layer work that does not need test labels is a dev cross-tab, and it should be run offline today without an upload. Three gates are narrower than “an exact copy exists,” and each is falsified by the labelled match rate inside the pairs it would suppress. If that rate stays near **0.96**, the gate deletes true duplicates. Do not tune any of them on the US test excess.

The first gate fires only when two Source 1 entities of the same name already occupy the two neighbouring numbers, so a Source 2/3 record at one number is being cross-linked to the other reference. It does not fire because one reference has a clean copy and a typo copy. It is still wrong if the two Source 1 rows are themselves duplicates, or if a common name collides on a common street. On dev, among **p ≥ 0.5** and absolute difference 1, and separately for same-parity difference 2, split pairs by whether a second Source 1 owns the other number. If that cell stays near **0.96**, do not suppress. If it falls well below the operating precision of the **p ≥ 0.5** set and the single-reference cell stays high, the gate is supported on dev, and the note that would accompany any later upload has to state how many labelled true pairs it drops. Stratify by name frequency. A high match rate only among rare names means the gate is mostly a common-name collision.

The second gate emits a neighbour pair only if the judge also agrees. It does not drop a neighbour because an exact sibling exists. It can still be wrong if the judge is already the component that dislikes a house-number mismatch, in which case the gate re-applies that dislike. The about **16k** judge-vetoed US pairs are not labelled false. On dev only, cross-tab judge agree against judge veto inside **p ≥ 0.5**, for difference 1, for same-parity difference 2, and for the one-character non-neighbour cell as a control. If vetoed neighbour pairs are still mostly labelled matches, the judge is not a precision filter for this pattern. A dev match rate near **0.96** inside the veto cell falsifies the gate. Report the labelled true-positive count in that cell, not the **16k** test-side count.

The third gate keeps every difference-1 or same-parity difference-2 pair whose house numbers are a one-character edit, and treats as the only suppression candidate the numeric step that is not a one-character edit, such as 19 versus 20 or 18 versus 20. That follows the separation of edit evidence from absolute difference, which Splink already ships as different levels with different weights ([Splink out-of-the-box comparisons](https://moj-analytical-services.github.io/splink/topic_guides/comparisons/out_of_the_box_comparisons.html)). It does not delete a typo-duplicate merely because a clean copy is present. It can still be wrong: the whole neighbour bucket is **96.3%** labelled matches, so the non-edit subset may still be mostly true duplicates, and Brummet’s housing-unit prior must not override this task’s labels. Split dev **p ≥ 0.5** pairs by numeric difference, parity change, and Levenshtein distance on the house string. Suppress a cell only if its match rate is materially below the operating precision of the **p ≥ 0.5** set. If the cell with difference 1 and Levenshtein distance greater than 1 is still around **0.95** or higher, this gate is falsified too. Inside each edit cell, also compute the interaction the original rule cares about: labelled match rate when an exact-house same-name candidate for the same Source 1 exists, versus when it does not. If the “exact also present” cell stays near **0.963**, “keep only the best-addressed candidate” is falsified on dev even for the non-edit subset.

For any cell, the maximum false pairs removed, as a share of confident dev pairs, is the cell’s share times one minus its labelled match rate. For the entire off-by-one slice that bound is about **0.017%** of confident pairs. Macro F0.5 will not show the recall damage. The quantity to write down is the count of labelled true pairs removed. None of the three gates should be uploaded on the marginal **0.96** rate, and none of them should be uploaded in place of **A** or **B**. The dev match rates inside the proposed cells were not supplied. The falsification procedure is specified. The outcome is unknown. Until those cells are computed, the supported decision-layer action is to keep the neighbour.

## Write the branch as membership in the training-label set, and hash both TSVs

The package a reviewer re-runs is one non-interactive command that rebuilds both TSVs from the provided data plus pinned scores. A notebook that cannot be re-run is not that artifact. Kaggle’s winner guidelines ask for code capable of generating the winning submission, exact dependency pins, a settings file as the only source of paths, separate prepare, train, and predict entry points, and a serialized model so prediction does not retrain ([Kaggle Winning Model Documentation Guidelines](https://www.kaggle.com/WinningModelDocumentationGuidelines); [ICR competition rules](https://www.kaggle.com/competitions/icr-identify-age-related-conditions/rules)). DrivenData asks for inference from raw competition data plus weights, from a fresh system, with no manual input, and says the inference step should run on any new set of data whether or not it was in the test set ([DrivenData prize-winner template](https://github.com/drivendataorg/prize-winner-template); [README template](https://raw.githubusercontent.com/drivendataorg/prize-winner-template/main/README_template.md)). Pineau’s checklist and the Papers with Code checklist both ask for the precise command that produces the reported result, and for the method used to select each hyperparameter, not only the final value ([Pineau checklist v2.0](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist.pdf); [Papers with Code completeness checklist](https://github.com/paperswithcode/releasing-research-code/blob/master/README.md); [NeurIPS paper checklist](https://neurips.cc/public/guides/PaperChecklist)). Kaggle’s published success criterion is the leaderboard score within a reasonable margin. That is weaker than this contest. Public and private scores are two splits of one file, and the baseline must match the upload-time stacker byte for byte. A retrain that lands close is a different submission. The stitch command should check md5 of `output/matching_results.tsv` and `output/candidate_pairs.tsv` against digests recorded at upload time, and exit non-zero on mismatch. No organiser guide retrieved here requires that md5. The one-file split and the upload-time stacker do.

Define **C** at runtime as the set of country strings on training rows whose supervision label is present. Rows with a missing label do not contribute a country. **C** is not the literal pair of training-country names, not a one-hot vocabulary fitted with an error on unknown categories, and not the list of countries observed in the test file. The log is allowed to print the computed members. The branch must not compare a country string to a constant. The labelled-country policy applies if and only if `country ∈ C`. The no-label policy applies if and only if `country ∉ C`. Any future string absent from **C** takes the no-label policy. The held-out name does not appear in the branch, the settings file, the methodology, the comments, or the fixtures.

The labelled-country function is the upload-time decision for that policy: **U1** if **A** did not clear **0.985**, and **A**’s set if it did. Do not refit it inside the stitch step. The no-label function starts from **U1**. It undoes a judge veto only for a pair that is already in the pinned judge-score file and whose stage-2 score is at least **τ = 0.99**, then assigns each non-reference record to at most one reference. The tie-break is highest stage-2 score, then lexicographic pair id. Pairs that were never scored cannot be added back. **τ** is a scalar constant, not a function of the country string. Write the real provenance next to the value. The acceptable provenance is a constant fixed before this stitch, chosen on a validation slice drawn from countries in **C**, or simply declared as the constant of upload **B**. It must not be moved after **B**’s public score returns. If the value was in fact chosen by a sweep against the public leaderboard, the methodology has to say that. Renaming the sweep to “countries with no training labels” does not make it regenerable from the provided data. The public board is one split of the same submitted file. Choosing **τ** from that score uses held-out feedback rather than the training labels.

The join key is the id the scorer joins on, not the country string and not a row number. Country for the branch is looked up from the entity table, not from a country column copied into an old score file. Every required id appears in `matching_results.tsv` exactly once. That is a key constraint, not a claim that one reference matches only one non-reference. Each non-reference id has at most one reference. The set of country strings on the submission equals the set on the required ids, so it is not a subset of **C**. Every pair the stitched file treats as a match is a row of `candidate_pairs.tsv`, including the **8,506** add-backs. A pair inserted only at stitch time, with no score in the judge-score file, is not a candidate the model scored.

The command hash-checks the pinned stacker and the judge-score files, recomputes **C**, and fails closed if **C** disagrees with the set logged when the upload-time file was built and the md5 check is on. It then does not emit the old TSV under the old digest. Three fixtures use synthetic country strings, never the real held-out name. Appending a labelled training row with a new string **S** must move ids whose country is **S** onto the labelled-country policy. Removing all labels for one country that had been in **C** must move those ids onto the no-label policy. An entity whose country string is neither in the original **C** nor equal to any literal in the repository must still appear exactly once, under the no-label policy. A text search of code, settings, README, and methodology finds no branch on a country literal and no geocoder or gazetteer import. Printing **C** is allowed.

The methodology states the task as entity resolution over an open set of country strings, defines **C** in one sentence, and says the no-label policy is used because that country string has no training labels, so the labelled-country judge is not treated as calibrated there. It does not say the policy is used because of a language, a postal format, or an administrative geography. It states the invariants: every required id once, unseen country strings retained, each non-reference assigned at most once, one submitted file for both leaderboard splits. It says what was not used: no external database, no geocoder, no hand-built gazetteer, no country-name branch, no second file for the private split. Blocking, if it uses country at all, uses “same country string,” not an allow-list equal to the training countries. The model section records the name, an Apache-2.0 or MIT license, a parameter count at most **8×10⁹**, and a weight hash. Features are fields from the provided data or transforms of those fields. The judge score and the veto are defined from model outputs, not from a country. The other-information section records hardware, wall time, the exact command, the requirements pin, paths and hashes of the stacker and the judge-score files, md5 of both TSVs, and the dry-run command. It also records the limitation that a change in the training file’s labelled-country set fails the dry-run on purpose. The stitch is a pure function of the pinned scores and has no seed.

Sentences that fail review, even if a later code cleanup removes the call, are the ones that name the held-out country, call a geocoder or a commune gazetteer, one-hot the training pair and drop other countries, special-case a country after seeing the test file, sweep the veto threshold against the public score, or hand-label a sample of the public test. Hand labelling of test or validation records is the prohibition in the Kaggle rule text cited above. An external-data permission in some other contest’s rules does not apply. This contest’s ban on external databases, geocoders, and lookups wins. The sentence that matches the rule is: let **C** be the set of country strings on training rows that have a label, computed from the training file at runtime; where the entity’s country is not in **C**, keep the baseline, except that a veto is undone when the model score on a pair the model already scored is at least **0.99**; then assign each non-reference record to at most one reference.

## Conclusion

The public board can accept or reject two edits that were named before the scores returned. It cannot identify the judge’s new false-veto rate, it cannot label the extra US neighbours, and it cannot be divided by **0.15** to produce a country effect. Under macro F0.5 the only combination that preserves each parent’s entity score is a partition of whole predicted sets, and that partition’s public number is the sum of the region lifts only while no Source 2/3 id has two owners. Including a region whose own public delta is negative makes the stitch worse than the winner alone, so “both, or the one that cleared, or **U1**” is the decision the algebra supports. The optimism in whichever public number cleared the bar is real and unquantified in F0.5 points. The way to keep it from growing is to refuse every edit that was not on the menu, including a neighbour drop, a retuned **0.99**, and a prior inverted from a veto rate the labelled countries already showed cannot travel. The same open-set membership that makes the stitch legal is what the reviewer re-runs: **C** comes from the training file, the bytes match the upload-time digests, and the held-out name is never a branch.
