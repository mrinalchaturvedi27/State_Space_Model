# Region stitch risk when public and private scores split one test file

Scope: macro-averaged per-entity scores, row stitching by country, and selection on a public leaderboard that is a split of the same test file as the private board. No shake-up probability is stated for this contest. The public/private country mix is unpublished. Contest write-ups below are analogies; several use a time split, not a random half, and that difference is flagged.

Assigned setting (not re-derived): score is macro F0.5, the unweighted mean of per-reference-entity F0.5; a correct empty set scores 1.0; entities partition by country; true matches never cross countries; each non-reference record has at most one reference owner. The team submits the full test file; the organiser splits at scoring time. Baseline public score 0.985. Upload A replaces US and India rows with a second stacker and leaves France as baseline. Upload B changes France only, adding back about 8,506 pairs by undoing a judge veto at stage-2 p ≥ 0.99, with each non-reference record kept for at most one reference. Planned rule: if both beat 0.985, ship both changes; if one does, ship that one; if neither, keep the baseline.

## Is a country-row replacement the same as an entity-share mixture of the two files' scores, and when does stitching fail?

### Takeaway
No. For an unweighted mean of per-entity scores, a clean country replacement equals an entity-count mixture of the *region-restricted* means, not a mixture of the two files' overall scores. The identity fails as soon as one entity's prediction set is a hybrid, a global one-to-one rule rewrites claims that cross the cut, or the outer average is not the thing being mixed (micro F, or F of averaged precision and recall).

### Cited Findings
- Two different quantities are both called macro F1. "Averaged F1" is the arithmetic mean of per-class F1: (1/n) Σ F1_x. "F1 of averages" is the harmonic mean of the average precision and the average recall. They differ whenever some class has precision ≠ recall, and the gap can be as large as 0.5. They can rank two classifiers in opposite orders. — [Opitz and Burst, arXiv:1911.03347](https://arxiv.org/abs/1911.03347)
- Opitz and Burst set precision, recall, and F1 to 0 when the denominator is zero. That is not the team's rule that a correct empty set scores 1.0. — [Opitz and Burst, arXiv:1911.03347](https://arxiv.org/abs/1911.03347)
- A survey of classification metrics treats a real macro-average as class-decomposable: an unweighted mean of class-specific scores, so each class contributes equally regardless of how many instances it has. — [A Closer Look at Classification Evaluation Metrics, TACL](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00675/122720/A-Closer-Look-at-Classification-Evaluation-Metrics)
- In record linkage, one-to-one links are a linear assignment problem: maximise the sum of pair weights subject to each record on file A matching at most one record on file B and conversely. Jaro (1989) is the usual citation for casting Fellegi–Sunter weights as that program. — [Jaro, JASA 1989, abstract](https://www.tandfonline.com/doi/abs/10.1080/01621459.1989.10478785); [R Journal 2019-008, "The optimization problem in record linkage"](https://journal.r-project.org/articles/RJ-2019-008/RJ-2019-008.pdf)
- A greedy one-to-one pass is not optimal, because of transitive conflicts. Febrl drops pairs below a threshold, pulls out records that appear in only one pair, extracts each connected component of the remaining pairs, and solves each component with Bertsekas's auction algorithm. Linkage (two files) and deduplication (one file) are different: the same integer id in two files is not the same record. — [Christen, Febrl 0.3, "Record Pair One-To-One Assignment Restrictions"](https://users.cecs.anu.edu.au/~Peter.Christen/Febrl/febrl-0.3/febrldoc-0.3/node67.html)
- The same one-to-one constraint is still described as under-served after Jaro: later work treats it as a sparse linear-sum assignment on the bipartite graph of candidate pairs, not as independent thresholding. — [Enamorado, Fifield, and Imai-related thesis discussion of Jaro 1989 and fastLink, CMU](https://kilthub.cmu.edu/ndownloader/files/22801598)

### Inferences
- Because macro F0.5 in this setting is an unweighted mean of per-reference-entity scores, it is the same kind of object as Opitz and Burst's averaged F1, not their F1-of-averages. The outer mean is linear in the entity scores even though F0.5 inside an entity is a nonlinear function of that entity's TP, FP, and FN (β = 0.5 puts more weight on precision than F1 does). Linearity is only across entities.
- Let entities be partitioned into countries, and let the stitched file give every entity in country c the entire predicted set from file f_c. If entity e's score depends only on e's own predicted set versus e's gold set, then the stitch score is exactly Σ_c (n_c / N) · M_c(f_c), where M_c is the unweighted mean of per-entity scores inside country c and n_c is the number of reference entities in c. The weights are entity shares, not pair shares, not row shares, and not equal country weights. About 8,506 France pairs do not say what France's entity share is.
- That is not Σ_c (n_c / N) · S(f_c), where S(f_c) is file f_c's overall macro score. The overall score of the stacker file still includes its France (and other-country) entities. Those terms cancel out of the stitch only if you subtract them. Writing w · S(A) + (1 − w) · S(B) leaves a mixture of the regions you meant to throw away.
- If A differs from baseline only on US and India entities, and B differs only on France entities, and the stitch copies whole entity sets, the same linearity gives S(stitch) = S(A) + S(B) − S(baseline), on whatever entity set is being averaged (full file, or the public slice, if the slice is a subset of entities and each scored entity is taken entirely from one parent). Each country's entities are counted once. Averaging S(A) and S(B), or adding both lifts on top of the better file, counts the shared baseline countries twice.
- Row-wise stitching fails that identity under any of these couplings:
  1. Shared claim on one non-reference record. Gold never crossing countries does not stop a prediction from crossing. The stacker can assign a Source 2/3 id to a US reference while the France file assigns the same id to a France reference. Each parent file can still obey "at most one reference owner." The union does not. If the scorer scores each reference entity's set independently, macro F0.5 still adds — the double claim is just an FP (or a TP) inside each entity — but the file is illegal relative to the task constraint. If the scorer enforces a global one-to-one (drops one edge, or re-solves an assignment, as in Jaro / Febrl), then the prediction set of at least one entity is no longer the parent file's set, and S(stitch) is not S(A) + S(B) − S(baseline).
  2. One-to-one constraints whose conflict component crosses the cut. Febrl's connected components are exactly the case where a local greedy choice in one country changes the feasible match in another. Resolving inside the component couples the two files. Greedy "keep the higher stage-2 probability" is well-defined but is not the same as either parent, and Febrl notes greedy is not the optimal assignment.
  3. Candidate lists that differ. "Replace rows" is well-defined only if the submission is a set of predicted pairs and the whole set for each reference id is copied from one file. If the merge is "use the stacker's decision when both files scored that candidate, otherwise keep the baseline candidate," the entity's positive set is a hybrid. Its F0.5 equals neither parent. The same failure happens if row indices are aligned across files of different lengths, or if only pairs present in both files are overwritten.
  4. Empty predictions. An entity with a correct empty set has no rows. A row-overwrite or a concatenation does not delete the other file's pairs, so the stitch silently unions. Under the team rule that empty-and-correct scores 1.0, dropping or keeping that entity moves the macro by a full 1/N, not by a pair weight. Opitz and Burst's convention (undefined F → 0) would score that same entity differently; do not import it.
  5. Mixing inside the entity, or mixing precision and recall instead of F. Averaging the two files' global precision and recall and then taking one F0.5 is Opitz and Burst's other formula. It is not the macro of the stitch, and it can reverse a ranking.
  6. Public slice that cuts through an entity. F0.5 of a partial pair set is not a weighted average of anything simple, because it is a ratio. If the organiser scores only a random subset of pairs inside entities, the public number is not the entity-share mixture of the full-file region scores, even when the stitch itself is a clean partition. Country mix of that slice is unpublished, so a public delta cannot be inverted into a per-country effect. If instead the slice is a subset of whole entities and the scorer averages those entities, the additive identity still holds on the public entities alone — but the weights are the public slice's entity counts, which need not match the full-file country shares.

### Gaps
- The organiser's split unit (reference entity, pair, or row) and the scorer's treatment of a Source 2/3 id claimed by two Source 1 ids are not published. Which failure mode is active cannot be settled from the outside.
- No source was found that writes the mixture identity specifically for macro F0.5 in entity resolution. The identity above is the unweighted-mean algebra applied to the team's metric, not a quoted theorem.
- Opitz and Burst's empty-set convention conflicts with the team's 1.0 rule. How this contest codes the undefined precision of a true non-match was not found in the metric literature searched here.

## What is the selection bias of shipping the variant that improved on a random public half?

### Takeaway
A file chosen before any score is seen has a public score that is an unbiased estimate of that same file. Shipping whichever of two or three files looks better on the public half is the winner's curse: the reported public lift is biased high by a fraction of the standard error of the contrast, and on a complementary half the private contrast moves the other way when the metric really is an average over the split units. A pre-registered stitch file is not the same object as a pre-registered rule that still picks after seeing which upload won. There is no standard formula that turns a macro-F0.5 near 0.985 into a shake probability for this contest.

### Cited Findings
- If the classifier is chosen independently of the holdout, a bounded loss concentrates: Hoeffding plus a union bound. Once the next submission can depend on previous scores, that bound does not apply, and the public score is no longer an unbiased estimate of the true score. Kaggle's usual defence is a second, private slice of the test set plus limits on resubmission and displayed precision. — [Blum and Hardt, "The Ladder," arXiv:1502.04585](https://arxiv.org/abs/1502.04585)
- On the full-disclosure (Kaggle-style) leaderboard, Blum and Hardt's boosting attack drives public 0/1 loss down by Ω(√(k/n)) after k submissions while the untouched private coordinates stay at chance. Their parameter-free Ladder only returns a new score when a paired comparison beats the previous best by about one standard error of the paired difference, and they report that this attack then cannot do better than the usual maximum deviation of k non-adaptive guesses, on the order of √(log(k)/n). The Ladder's worst-case leaderboard error is O((log(kn)/n)^(1/3)); a lower bound of Ω(√(log(k)/n)) holds even for non-adaptive submissions. — [Blum and Hardt, arXiv:1502.04585](https://arxiv.org/abs/1502.04585)
- Hardt's illustration of the same attack on a model of the Heritage Health Prize public board moved a simulated entry from 0.462311 (about rank 146) to 0.451868 (about rank 6) in on the order of 700 submissions, with no gain on labels outside the public holdout. He marks those ranks as dependent on modeling assumptions, not as an attack that was actually submitted. — [Hardt, "Competing in a data science contest without reading the data"](https://blog.mrtz.org/2015/03/09/competition.html)
- The minimum of a cross-validation curve is biased downward as an estimate of test error at the chosen tuning point, because the same comparisons both pick the point and score it. Tibshirani and Tibshirani's adjustment uses only the already-computed fold curves. In a no-signal classification setting their Theorem 1 says the expected CV error of the selected rule is at most the true error. In simulations the optimism was large mainly when p ≫ n, and it differed by classifier; with a real signal and p < n the gap was often a few thousandths of error rate. They warn that comparing raw CV numbers across model classes is misleading when the selection bias differs. — [Tibshirani and Tibshirani, Annals of Applied Statistics 3(2):822–829, 2009](https://arxiv.org/abs/0908.2904)
- Across 120 Kaggle competitions, Roelofs, Recht, Hardt, Schmidt, and coauthors found little adaptive overfitting on classification-accuracy contests: public and private scores lined up, and where a gap remained it was typically under about 1 percentage point of accuracy, including among many submissions (they mention contests with up to 35,000 submissions). Outliers tended to have non-i.i.d. splits or an effectively small test set. This is not a macro-F0.5 result and is not a shake probability. — [Roelofs et al., NeurIPS 2019](https://papers.nips.cc/paper/9117-a-meta-analysis-of-overfitting-in-machine-learning)
- Recht, Roelofs, Schmidt, and Shankar built new CIFAR-10 and ImageNet test sets and found accuracy drops of about 4–10% (CIFAR-10) and 11–14% (ImageNet) relative to the original test sets. They attribute the drop to a harder new draw, not to adaptive overfitting: gains on the original test set still translated, and more recent higher-accuracy models dropped less. A fresh test distribution is a different risk from a random split of one file. — [Recht et al., "Do CIFAR-10 Classifiers Generalize to CIFAR-10?", arXiv:1806.00451](https://arxiv.org/abs/1806.00451); [Recht et al., ICML 2019, ImageNet](https://proceedings.mlr.press/v97/recht19a.html)
- Whitehill shows a different failure: a log-loss oracle on the test labels can be queried to recover those labels. On the Intel & MobileODT Cervical Cancer Screening public stage he reports log-loss 0.00000 and rank 4 of 848 with no task classifier, and he also treats an oracle that only scores an unknown fixed subset. That is label extraction from a smooth proper loss, not selection among two hard match files. — [Whitehill, arXiv:1707.01825](https://arxiv.org/abs/1707.01825)
- For a normal mean of 0 and scale σ, the half-normal (absolute value, or a zero-mean normal truncated to stay positive) has expectation σ √(2/π) ≈ 0.798 σ. — [Wikipedia, "Half-normal distribution"](https://en.wikipedia.org/wiki/Half-normal_distribution)
- For two independent standard normals, a direct calculation on Math Stack Exchange gives E[max(X, Y)] = E[|X − Y|]/2, and a numerical evaluation of the mean is reported as 0.5641895835…. That figure matches 1/√π. The thread's closed form is for the independent case; the comment thread does not cleanly state the correlated formula. — [Math Stack Exchange, "Maximum of two standard normal distribution"](https://math.stackexchange.com/questions/4527964/maximum-of-two-standard-normal-distribution)
- An upper bound often quoted for the expected maximum of n independent standard normals is √(2 log n). It is an upper bound, and it is loose for small n. — [Gwern, "Order Statistics"](https://gwern.net/order-statistic)
- For jointly normal variables, Clark (1961) gives exact moment formulas for the maximum when n = 2, including unequal means, unequal variances, and correlation, and says n > 2 is cumbersome enough that one approximates by iterating the two-variable formula. — [Clark, Operations Research 9(2):145–162, 1961](https://doi.org/10.1287/opre.9.2.145)
- In genome-wide association studies the winner's curse is the same selection effect: the SNP with the largest estimated effect has an exaggerated estimate. Ranking bias (the top of a long list) and threshold bias (anything that passes a cutoff) are distinguished, and both shrink on a fresh sample. — [Review of winner's-curse corrections, PLOS Genetics 2023](https://journals.plos.org/plosgenetics/article?id=10.1371/journal.pgen.1010546)

### Inferences
- Two different decisions are being conflated in the planned rule. Committing to one stitched file before either public number is used is static holdout evaluation: Blum and Hardt's unbiasedness argument applies to that file, and the public score differs from the full-file score only by split noise. The rule "if A beats 0.985 ship A; if B beats 0.985 ship B; if both, ship both; else baseline" is a pre-registered menu, but the file that is shipped still depends on the public scores. Tibshirani and Tibshirani's point applies: the same slice both picks and is then quoted as the performance of the pick. That is smaller than searching over regions after the fact, and it is not zero.
- Choosing the stitch after seeing which region won is a larger search. With countries assigned independently to one of two parents, three countries are eight stitched files, all judged on one public slice. The planned menu is only {baseline, A, B, both}, and "both" is determined by A and B if the additive identity in the previous section holds. It is not eight independent looks. It is also not one pre-registered file.
- Magnitude, when the noise really is Gaussian. These are standard order-statistic facts, not a published macro-F0.5 formula, and they are not a shake probability.
  - One pre-registered contrast, true effect zero, ship only if the public delta is positive. Conditional on shipping, the expected public delta is the half-normal mean, σ √(2/π) ≈ 0.80 times the standard error of that delta. The unconditional expected public delta (counting "did not ship" as zero) is half of that, about 0.40 SE, because the positive part is taken half the time.
  - Two variants with the same true score and independent public noise of SD σ: the expected public score of the winner sits σ/√π ≈ 0.56 σ above the common true score. Check: X − Y has SD σ√2, E[|X − Y|] = σ√2 · √(2/π) = 2σ/√π, and E[max] = E[|X − Y|]/2 = σ/√π, which matches the 0.5641895835 figure.
  - Same two variants but correlated with correlation ρ (the usual case: same public entities, files that agree on most entities). The SD of the difference is σ √(2(1 − ρ)), and the same identity gives E[max] − μ = σ √((1 − ρ)/π). High agreement shrinks the bias of the level. The relevant SE is the SE of the delta, not the SE of the macro score of the whole file. A France-only edit is noisy to the extent France entities in the public slice disagree, not to the extent the whole file's macro is noisy.
  - For three or four variants there is no equally standard one-line expectation in the sources above. Clark's practical recipe is to iterate the n = 2 formula, which approximates. The bound √(2 log K) σ is about 1.18 σ for K = 2, already twice the exact 0.56 σ, so it should not be used as the bias at K = 2 or 3. Blum and Hardt's √(log(k)/n) scaling is the right large-k shape for the best of k fixed submissions; at k = 2 or 3 it is the same order as one SE of the public mean, times a small log factor, not a new constant special to macro F.
- Complementary random half, and only if the score is exactly an average over the split units. If every entity (or other additive unit) is wholly in public or wholly in private, and both slices are halves, then for any fixed file S_full = (S_pub + S_priv) / 2, so S_priv = 2 S_full − S_pub. Public luck is then private un-luck of the same size. If the true delta versus baseline is 0, the expected private delta given that the public delta was positive is about −0.80 times the SE of the public delta. The sign flip is an expectation under a zero true effect, not a prediction that this team's private score will fall.
- That complement identity dies if the split cuts inside entities. Public F0.5 and private F0.5 of the same entity are not linear pieces of the full-entity F0.5. Then a lucky public half does not mechanically imply an unlucky private half by the same amount. Because the split unit and the country mix are unpublished, neither the 0.80 SE story nor any other numeric shake chance is available for these uploads.
- Roelofs et al.'s "typically under 1% accuracy" is the wrong yardstick to import. It is classification accuracy, large test sets, and mostly i.i.d. splits, after a whole contest of adaptation. A macro F0.5 already at 0.985 moves only when the edited entities move, and those entities may be a small fraction of a random public slice. The SE that multiplies 0.56 or 0.80 is the SE of that small contrast. It was not estimated here, and it cannot be read off 0.985.
- Recht et al. do not raise the shake risk for a random split of one file. Their drops are a new sample from a slightly different distribution. Using them as a prior for this private board would invent a shift the organiser has not described.
- Whitehill's label-recovery attack is not what two full-file uploads do. It would become relevant only if many coordinate-level probes were used to mine the public slice. Two or three files do not extract test labels from macro F0.5.
- Pre-registered stitch versus post-hoc region choice, in one line: the pre-registered file has E[public] = E[private] = full-file score (under an entity split and no selection). The planned threshold rule biases the quoted public number of whichever file passes. Looking at per-country public contributions and then assigning each country to the parent that won adds a further selection over the country partition, on the same slice, which is the Tibshirani problem with a larger menu. The regions in A and B are already fixed (US+India vs France); using the public scores only to accept or reject those two pre-specified edits is the smaller menu, not a licence to retile countries after the scores return.

### Gaps
- No source gives a ready-made bias, in macro-F0.5 points, for "two or three variants, private board a random half, baseline 0.985." The 0.56 SE and 0.80 SE figures are Gaussian order statistics. They are not a contest formula, and they are not a probability that the private score falls below 0.985.
- The SE of this macro score, the correlation between A, B, and baseline on the public slice, and the fraction of reference entities each edit touches were not in the sources. Without them the order-statistic factor cannot be converted into F0.5 points.
- Whether this organiser's public and private slices are complementary halves of entities, a non-half split, or a row split inside entities is unknown. The complement identity is conditional on the first of those.
- Clark's n = 2 formula was not re-read from the 1961 PDF in this pass; the citation is the paper's abstract and secondary descriptions. The equal-mean special case used above was derived from the absolute-difference identity plus the half-normal mean, not copied from Clark's tables.
- Roelofs et al. do not break out entity-resolution or macro-F contests. Their "little overfitting" conclusion should not be read as a bound for this leaderboard.

## Where did a segment blend beat a global blend, and where did it overfit the public board?

### Takeaway
Named cases exist in both directions, but the clean overfits are time-split forecasting contests, not a random split of one entity-resolution file. Per-site models in ASHRAE rose from 12th on the public board to 2nd on the private board. Country multipliers tuned on the public slice of Forecasting Mini-Course Sales moved from public SMAPE 6.08955 to private 7.21200. Neither result is a shake probability for this test file.

### Cited Findings
- ASHRAE Great Energy Predictor III, 2nd-place write-up (team finished 2nd private, 12th public): they trained boosting models at several cuts, including a separate model per site and meter, per building and meter, per building type and meter, and on the full training data. They call a separate model per site very useful because sites did not share one parameter set. The final ensemble was about 30% bagged XGBoost, 50% bagged LightGBM, 15% bagged CatBoost, and 5% a feed-forward net, with weights chosen from CV, the public leaderboard, leaked rows, and intuition. They also list "leak insertion" as part of the solution and describe it as ugly and probably not decisive. — [cha0s, "2nd Place Solution," ASHRAE – Great Energy Predictor III](https://www.kaggle.com/competitions/ashrae-energy-prediction/writeups/cha0s-2nd-place-solution)
- Forecasting Mini-Course Sales (Playground Series S3E19), Mateusz Kowalczyk write-up: a simple model landed near 70th; a mean blend of the best public submissions reached 17th on the private leaderboard (top 2%). Separately, country multipliers probed on the public board — Argentina 4.5, Spain 1.6, Japan 1.2, Estonia 1.7, Canada 0.9 — scored 6.08955 public and 7.21200 private. Lower SMAPE is better, so the probed country map got worse on the private slice. — [Kowalczyk, "Blending best public submissions – 17th," Forecasting Mini-Course Sales](https://www.kaggle.com/competitions/playground-series-s3e19/writeups/mateusz-kowalczyk-blending-best-public-submissions)
- Same contest, discussion thread: country-specific multipliers were proposed specifically to be tuned on the leaderboard, with manual search (try ±0.25 and keep the step if the public score improved). Posted trial values included Argentina around 2.25–4, Spain around 1.75–2, Japan around 1.5, Estonia around 2, Canada around 1. — [Forecasting Mini-Course Sales discussion](https://www.kaggle.com/competitions/playground-series-s3e19/discussion/425252)
- Same contest, 3rd-place write-up: private score used the last 75% of 2022, so the public slice was the earlier part of that year, not a random half of one period. The author fit a separate model per product (five models), not a leaderboard search over countries, and set the 2022 level of total daily sales by leaderboard probing. Validation SMAPE was 4.87. — [Albert Zhang, "3rd Place Solution: EDA is the key"](https://www.kaggle.com/competitions/playground-series-s3e19/writeups/albert-zhang-3rd-place-solution-eda-is-the-key)
- Tabular Playground Series – January 2022, organiser statement: the public leaderboard is the first quarter of the test year and the private leaderboard is the remaining three quarters. The task is sales by country, store, and product. — [TPS Jan 2022 data page](https://www.kaggle.com/c/tabular-playground-series-jan-2022/data)
- Same contest, private leaderboard: first place AmbrosM at 4.58941 (SMAPE, lower better). — [TPS Jan 2022 leaderboard](https://www.kaggle.com/competitions/tabular-playground-series-jan-2022/leaderboard)
- A secondary write-up compilation attributes to that winning linear model country GDP, country consumer confidence, and country-specific holidays, with public score 4.11991 (about the 19th percentile, worse rank than private) and the same private score 4.58941. The public rank was not re-read from Kaggle's own public leaderboard in this pass. — [Hakky Handbook, TPS Jan 2022 solution notes](https://book.st-hakky.com/data-science/tabular-playground-series-jan-2022)
- Kaggle's own discussion culture describes "blending" that searches weights on the public board, as opposed to weights fit on out-of-fold predictions, as the version that overfits the public slice and then shakes. That advice is general; it is not a country-stitch result. — [Used Car Prices discussion](https://www.kaggle.com/competitions/playground-series-s4e9/discussion/535473); [Exploring Mental Health Data discussion](https://www.kaggle.com/competitions/playground-series-s4e11/discussion/543929)

### Inferences
- The ASHRAE 2nd-place result is the clearest named case in which a segment model (site, and site × meter) was reported to beat relying on one global fit, and the private rank (2nd) was better than the public rank (12th). It is not a pure win for "ignore the public board." The same write-up set some ensemble weights with the public score and inserted leaked rows. The rise is evidence that site-specific fits can survive the private slice, not evidence that any country stitch will.
- The Mini-Course Sales country map is the clearest named case in which a segment post-process (one multiplier per country), chosen because it improved the public score, was worse on the private slice: 6.08955 public versus 7.21200 private. A global-style mean of strong public submissions still reached 17th private, so "segment" was the part that overfit in that write-up, while a dumb global blend of public files did not collapse all the way. The 3rd-place note says the private slice was the last 75% of 2022. The public quarter is not exchangeable with the rest of the year. That is a temporal shift, closer to Recht's "new draw" problem than to a random half of one file. It does not license a numeric shake chance here.
- TPS January 2022 is the same pattern, documented by the organiser: public = first quarter, private = the rest. Country-level covariates (GDP, country holidays) were part of a winning model that was relatively better on the private board than on the public board, if the secondary compilation's public score is right. The lesson that matches this team is narrower: a public slice that is not a random subset of the same units will reward segment tweaks that only fit that slice. It is not evidence about US/India/France entity shares.
- Nothing found was an entity-resolution contest scored by macro F0.5 in which a country stitch of two match files was compared with a global blend on a random public/private split. Importing 6.09 → 7.21, or 12th → 2nd, as this contest's gap would invent a result.

### Gaps
- The full ASHRAE and Mini-Course Sales write-up pages did not return body text on a direct fetch (Kaggle served a shell page). Numbers and ranks above are from search snippets of those URLs, not from a re-read of the full posts. If a snippet truncated a caveat, it is not repeated here.
- ASHRAE's public/private split mechanism was not re-established from the competition data page in this pass. Do not treat that contest as a verified random half.
- The Hakky Handbook public score and percentile for AmbrosM were not checked against Kaggle. Only the private score 4.58941 was seen on the Kaggle leaderboard snippet.
- No write-up was found that isolates "stitch predictions by country" versus "average the two submission files globally" on a random split of one test file, with both public and private numbers. The gap is the design this team is actually running.

## What should be computed on the two uploaded files before stitching?

### Takeaway
Before any stitched file is treated as scored, check three computations on the uploaded files: the symmetric difference is confined to the intended reference-entity countries, no Source 2/3 id in the stitch has two Source 1 owners, and the public number quoted for the stitch is S(A) + S(B) − S(baseline) rather than an average or a sum of lifts. If the one-to-one check fails and pairs are dropped, that formula is no longer the public score.

### Cited Findings
- One-to-one linkage is an assignment on pairs, not an independent per-pair threshold. Conflicts have to be solved on the connected component, and a record that appears in only one pair can be left out of the solver. — [Febrl one-to-one notes](https://users.cecs.anu.edu.au/~Peter.Christen/Febrl/febrl-0.3/febrldoc-0.3/node67.html); [Jaro 1989](https://www.tandfonline.com/doi/abs/10.1080/01621459.1989.10478785); [R Journal 2019-008](https://journal.r-project.org/articles/RJ-2019-008/RJ-2019-008.pdf)
- The public score of a file that was chosen because it won a comparison is a biased estimate of that file's true score. A paired comparison is the variance that matters when two submissions agree on most rows: Blum and Hardt's parameter-free Ladder tests the mean of the per-row loss difference against the standard deviation of that difference, not against the standard deviation of either score alone. — [Blum and Hardt, arXiv:1502.04585](https://arxiv.org/abs/1502.04585)
- Macro-averaged F is a mean of per-class scores. A different aggregation, the harmonic mean of averaged precision and averaged recall, is not the same number and can reverse rankings. — [Opitz and Burst, arXiv:1911.03347](https://arxiv.org/abs/1911.03347)
- Selecting on the minimum (or maximum) and then quoting that same number double-uses the sample. The bias correction literature exists because the selected score is not an independent measurement. — [Tibshirani and Tibshirani 2009](https://arxiv.org/abs/0908.2904)

### Inferences
- Do these checks on the two uploaded files and the baseline file they were built from. None of them uses labels or the leaderboard.
  1. Key every row as a predicted pair (Source 1 id, Source 2/3 id), not as a physical line number. Files with different pair counts do not have aligned rows.
  2. Attach each pair to the reference entity's country. Confirm the symmetric difference A versus baseline touches only US and India reference ids, and B versus baseline touches only France reference ids, including pairs that were deleted rather than added. If any other country differs, A and B are not single-region edits, and adding their lifts attributes shared edits twice.
  3. Build the stitch by entity, not by concatenation. For every US and India reference id, the predicted set in the stitch must equal A's set, including the empty set. For every France reference id, it must equal B's set. For every other reference id, it must equal the baseline set. Concatenation keeps pairs the new file had removed and double-inserts pairs present in both.
  4. One-to-one on the stitch, which is the check neither parent file can pass by itself. Map each Source 2/3 id to the set of Source 1 ids that claim it. Any id with two or more Source 1 owners is a cross-cut conflict (or a within-country bug). Also re-check that each parent already satisfies the constraint; B's 8,506 restored pairs were supposed to keep one owner each, but that does not bind the union with A's US and India pairs. Febrl's component extraction is the right object: isolated pairs are fine; a component that touches both a kept US entity and a kept France entity is the coupling that breaks the score identity.
  5. If that set is empty, and the scorer does not itself reassign across entities, the public score of the stitch is S_pub(A) + S_pub(B) − S_pub(baseline), not the mean of the two public scores and not baseline plus both lifts. That expression counts each public entity once. It is an accounting identity under the conditions in the first section, not a second experiment. Quoting it beside S_pub(A) and S_pub(B) as if three independent leaderboard runs had confirmed the stitch double-counts one public slice. The variance of the inferred lift is the variance of the sum of the two region deltas on that same slice.
  6. If the conflict list is not empty, do not use the identity. Resolve without labels: inside each connected component, keep a single Source 1 owner per Source 2/3 id by a rule fixed in advance (higher stage-2 probability, or the parent that was pre-registered for that reference's country), which is the greedy end of what Febrl replaces with the auction algorithm. Record the reference ids whose sets changed. Each such entity can move the macro by at most 1/N, because F0.5 is at most 1 and at least 0 under usual coding (the team's correct-empty score of 1.0 is inside that range). If (number of touched reference entities) / N is smaller than the inferred lift, the sign of the lift survives the repair; if it is not, the inferred public score is not a score. The repaired file is a new submission. Its public number, once the organiser scores it, is the measurement. The sum of A's and B's lifts is then only a bound.
- Do not read "both A and B beat 0.985" as two replications of the stitch. A did not contain the France edit, and B did not contain the US/India edit. Under the identity, the stitch's public lift is the sum of the two lifts, so it is larger than each, but only the disjoint-country check makes the sum legal. If that check passes, shipping both because each beat 0.985 is the same decision as shipping the stitch because the inferred public score beats 0.985. It still has the winner's-curse bias of the previous section, because both lifts were accepted on the public slice. It does not have an extra bias from averaging the two leaderboard rows.
- A public score computed this way is not double-counting entities. Double-counting would be: averaging the two public scores; adding both lifts to the better score; counting one Source 2/3 id as a true positive for two Source 1 ids; or treating S(A) and S(B) as two independent estimates of S(stitch). The paired-difference remark from Blum and Hardt is why the right uncertainty is the SD of the per-entity score difference on the entities the two files do not share, not the SD of either macro score and not a fresh-submission SE.
- Weight the mixture audit by reference entities, not by the 8,506 pairs. A country with many pairs and few reference entities is a small term in macro F0.5 and a large term in a row-weighted blend. Those two blends are different files' scores.

### Gaps
- The submission column names, and whether the organiser's scorer already drops a second claim on a Source 2/3 id, were not in any public source. The checks above are defined on the files the team uploads; they do not reveal which penalty the organiser would have applied.
- No published entity-resolution scoring script was found that states the empty-set convention together with a one-to-one penalty. The bound of 1/N per touched entity assumes F0.5 stays inside [0, 1] and that no extra global penalty is added on top of the per-entity mean.
- The public country mix remains unknown, so these file checks can certify the additive identity on the full file and can stop an illegal double claim. They cannot turn the two public scores into a per-country confidence interval.
